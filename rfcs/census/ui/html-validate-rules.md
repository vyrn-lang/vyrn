# UI census, source 5: html-validate rules

One row per built-in rule indexed at <https://html-validate.org/rules/> (94 rules on 2026-08-23). Column semantics match `nuxt-hints-rules.md` (source 4).

`when it can be checked` names the information a check needs and whether the `.vyx` template text carries it:

- `COMPILE TIME` — the template text alone decides. Attribute-presence rules stay here even when the value is bound; presence survives any binding.
- `EITHER` — a literal value or static structure decides at compile time; a bound value or cross-component reference escapes it and needs the rendered page.
- `RUN TIME` — only the composed document decides.

The parse tree that `std/vyx-hints.vyrn` walks carries element tag, a component flag, attributes (name, event flag, dynamic flag, literal value, line, column), children, line numbers, and `v-for`/`v-if` structure (`std/vyx-hints.vyrn:221-233`, attribute reads at `std/vyx-hints.vyrn:295-389`, control-flow context at `std/vyx-hints.vyrn:276-283`). It keeps no raw spelling: no whitespace between tokens, no quote characters, no comment nodes. Component calls are skipped by every element rule (`std/vyx-hints.vyrn:285-288`).

## The overlap target

Nuxt Hints does not have its own HTML rules for this area. Its `htmlValidate` feature embeds html-validate itself and runs it on every server-rendered response (`https://raw.githubusercontent.com/nuxt/hints/refs/heads/main/README.md`, "HTML Validate integration"). The configuration extends `html-validate:standard`, `html-validate:document`, and `html-validate:browser`, turns seven rules off, and forces `no-unknown-elements` to error (`https://github.com/nuxt/hints/blob/main/src/runtime/html-validate/nitro.plugin.ts`, `DEFAULT_EXTENDS`, `DEFAULT_RULES`). Per the preset table at <https://html-validate.org/rules/presets.html>, that enables 41 of the 94 rules: the 36 `standard` rules, 4 of the 5 `document` rules (`heading-level`, `input-missing-label`, `missing-doctype`, `no-missing-references`), and `no-unknown-elements`. `require-sri` is in the `document` preset but sits on the off-list. The remaining 52 rules live only in `recommended` or in no preset, so they never run inside Nuxt Hints. Nuxt Hints also stores a report only when `results.errorCount > 0`; a page whose findings are all warnings produces no report at all (`nitro.plugin.ts`, the `render:response` hook).

So the overlap column means one of three things:

- `yes` — Nuxt Hints runs this exact rule at RUN TIME on rendered HTML. Same rule, different moment: a compile-time port catches the fault before render, Nuxt Hints sees the fully composed document and so also catches faults across component boundaries.
- `named, off` — the rule is in a preset Nuxt Hints extends, but its config turns it off.
- `none` — outside the presets Nuxt Hints extends.

Where html-validate is stricter than Nuxt Hints:

- Standalone html-validate with the default `recommended` preset covers all rules except ten that carry no mark in any preset column: `allowed-links`, `attr-pattern`, `class-pattern`, `deprecated-class`, `id-pattern`, `name-pattern`, `no-style-tag`, `no-unknown-attributes`, `no-unknown-elements`, `svg-focusable` (<https://html-validate.org/rules/presets.html>).
