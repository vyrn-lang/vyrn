# Source 2 — reka-ui open-issue defect census

Census of real defects reported against reka-ui (https://github.com/unovue/reka-ui).
Purpose: feed the Vyrn component-library design. Each defect class gets a verdict:
could a compile-time check over `.vyx` templates and their types have caught it?

## Method

Read date: 2026-08-23. The census read 81 issues: the v3 roadmap epic #2721 in
full, plus 80 of the 220 open issues. The 80 cover every `[Bug]`-labelled issue on
the first page of `sort:created-desc`, the high-comment issues further back
(#1641, #1937, #1667, #1670, #2160, #1805), and the v3 contract proposals that
name present-day defects (#2823, #2732). Bodies came from the GitHub API for the
same issue pages listed at
https://github.com/unovue/reka-ui/issues?q=is%3Aissue+is%3Aopen+sort%3Acreated-desc .
Every claim below cites its issue URL.

## Issue #2721 quoted verbatim

Source: https://github.com/unovue/reka-ui/issues/2721 (`[Epic] v3 Roadmap`).

The epic is a tracking issue, not a bug report. Its problem statements appear as
the scope items it exists to fix:

> Tracking issue for **reka-ui v3**. This lays out scope and sequencing; each item links to its own issue.

> ## Core architectural decision
>
> **Components stay exported with their public API intact.** v3 re-architects them *internally*:
>
> - Each component's logic moves into a `useX()` **logic composable**.
> - The `.vue` SFC becomes a thin shell composing `useX()` + `useRender`.
> - `useRender` replaces the `Primitive` / `asChild` wrapper internally.
> - The logic composables become a **new additive public API** for programmatic control.

The named problems behind Phase 2, from the same body's roadmap entries:

> [perf: overlay & render performance overhaul #2724](https://github.com/unovue/reka-ui/issues/2724) — overlay & render performance overhaul

and, in the dependency-spine diagram:

> ├─ Performance overhaul (DismissableLayer shared stack; render overhead)
> └─ Full Shadow DOM support

So #2721 itself concedes three standing defect classes before any individual bug
report is read: render overhead in every component, a dismissable-layer stack
that needs rebuilding, and missing Shadow DOM support (#1667 shows the symptoms).

## Defect classes

| class | issues in it | what goes wrong | could a compiler have caught it | what the compiler would need to know |

| Dangling idref: a trigger emits `aria-controls` naming content that is not mounted | [#2882](https://github.com/unovue/reka-ui/issues/2882), [#2597](https://github.com/unovue/reka-ui/issues/2597) | A closed `SelectTrigger` renders `aria-controls="reka-select-content-…"` while "the content with that id only exists once the select is open. The reference therefore points at a missing element" (#2882). PR #2390 fixed this for `TabsTrigger` only; Select, Combobox, DropdownMenu and Popover still emit the dangling reference (#2597). Validators flag it on every page load. | PARTLY | That an idref attribute must name an element rendered under the same mount condition as the attribute itself; the compiler can then require either the target in the same template branch or an explicit "target mounts lazily" declaration on the pair. Whether the content is mounted at run time stays dynamic, hence PARTLY. |
| Contract drift between sibling triggers: same role, different toggle behaviour | [#2872](https://github.com/unovue/reka-ui/issues/2872) | `DrawerTrigger`'s click handler hard-codes open: "`@click="rootContext.onOpenChange(true, 'trigger-press')"`", while "`DialogTrigger` **toggles**: its click handler is `onClick: onOpenToggle`". A second click on the trigger of an open drawer "a complete no-op"; no `update:open` is emitted. | YES | That a component part named Trigger bound to a boolean open context must invert that context on activation, one rule shared by the whole Dialog/Popover/Drawer family; the compiler checks each trigger's handler against the family contract. |
| Focus control fails under real DOM state: traps steal, lose, or never restore focus | [#2886](https://github.com/unovue/reka-ui/issues/2886), [#2803](https://github.com/unovue/reka-ui/issues/2803), [#2211](https://github.com/unovue/reka-ui/issues/2211), [#2450](https://github.com/unovue/reka-ui/issues/2450), [#2128](https://github.com/unovue/reka-ui/issues/2128), [#1782](https://github.com/unovue/reka-ui/issues/1782), [#2056](https://github.com/unovue/reka-ui/issues/2056), [#680](https://github.com/unovue/reka-ui/issues/680), [#1296](https://github.com/unovue/reka-ui/issues/1296), [#1667](https://github.com/unovue/reka-ui/issues/1667) | "`FocusScope` moves focus to its container even though focus is, at that moment, already on a valid element inside that container" (#2886); a popover "dismisses itself in the same tick it opens" when content has no tabbable children (#2803); focus is not returned after repeated open/close (#2211); `openAutoFocus` fires once then never again (#2450); tabbing past an iframe or radio group breaks the trap (#2128); a NavigationMenu inside a Dialog skips its last link during tab cycling (#1782); Listbox autofocuses on mount (#2056); a fetch inside a watcher permanently kills dialog autofocus through MutationObserver timing (#680); Shadow DOM makes focus jump back to `DialogContent` (#1667). All depend on `document.activeElement`, browser focus semantics, and event timing. | NO | Nothing expressible about tags, attributes, or typed expressions determines where a browser puts focus across mount, unmount, and gesture timing. |
| Body-style ownership conflict: two subsystems write and restore one property on `<body>` | [#2867](https://github.com/unovue/reka-ui/issues/2867), [#2800](https://github.com/unovue/reka-ui/issues/2800), [#2403](https://github.com/unovue/reka-ui/issues/2403), [#1515](https://github.com/unovue/reka-ui/issues/1515), [#1540](https://github.com/unovue/reka-ui/issues/1540), [#1670](https://github.com/unovue/reka-ui/issues/1670) | "The underlying shape, two owners writing one property" leaves the body stuck at `pointer-events: none` with nothing open (#2867); scroll lock erases pre-existing `padding-right`/`margin-right` (#2800); the dialog shifts 8px when close removes body styles mid-animation (#2403); Apple Pencil input dies under the touch-action lock (#1515); users ask for the `pointer-events: none` on body not to exist at all (#1540, #1670). | NO | The values live in computed styles, scrollbars, and animation frames at run time; no template-level fact decides them. |
| Overlay dismissal coordination: concurrent floating layers do not dismiss each other | [#1787](https://github.com/unovue/reka-ui/issues/1787), [#2340](https://github.com/unovue/reka-ui/issues/2340) | Open a Combobox, then click a Select: "Combobox stays opened, Select appears" because "Select does not share DismissableLayer with Comobobx" (#1787). A TinyMCE modal inside a reka Dialog cannot take focus at all (#2340). Third-party layers sit outside the layer stack by construction. | NO | Layer membership is a property of live DOM events and foreign components the template does not name. |
| Gesture and platform timing sensitivity | [#2598](https://github.com/unovue/reka-ui/issues/2598), [#2200](https://github.com/unovue/reka-ui/issues/2200), [#1844](https://github.com/unovue/reka-ui/issues/1844), [#2783](https://github.com/unovue/reka-ui/issues/2783), [#2002](https://github.com/unovue/reka-ui/issues/2002), [#2292](https://github.com/unovue/reka-ui/issues/2292), [#2876](https://github.com/unovue/reka-ui/issues/2876), [#2877](https://github.com/unovue/reka-ui/issues/2877), [#2884](https://github.com/unovue/reka-ui/issues/2884) | A tooltip stays open if the cursor crosses fast enough (#2598); small iOS buttons swallow clicks (#2200); nested context menus both open on touch (#1844); Chrome suppresses `click` when focus-driven remounts replace the node between mousedown and mouseup (#2783); the last DateField segment overwrites itself forever (#2002); typeahead does nothing while the Select is closed (#2292); drawer drags are not axis-locked over scrollable content (#2876); the soft keyboard covers drawer inputs (#2877); highlighting scrolls the document "before Floating UI has placed the portalled Popper content" (#2884). | NO | Each failure needs pointer-event sequences, viewport metrics, or cross-subsystem ordering that exists only at run time. |
| Prop contract silently ignored or absent | [#2034](https://github.com/unovue/reka-ui/issues/2034), [#2142](https://github.com/unovue/reka-ui/issues/2142), [#2476](https://github.com/unovue/reka-ui/issues/2476), [#2548](https://github.com/unovue/reka-ui/issues/2548), [#2103](https://github.com/unovue/reka-ui/issues/2103) | "`:auto-focus="false"` prop doesn't work when `ComboboxInput` is placed inside `ComboboxContent`" (#2034); `@escapeKeyDown.stop` has no effect because the handler is not a real DOM-event binding (#2142); "TabsContent hardcodes force-mount when calling presence" (#2476); `SelectRoot` accepts no `id` prop at all, so label association needs workarounds (#2548); NumberField updates its value only on blur or Enter, so form code cannot track typing (#2103). | PARTLY | That every accepted attribute must have a read path in the component implementation, and that a wrapper must forward attributes a parent may set (`id`, `aria-*`); the compiler can reject dead props and unforwarded standard attributes. It cannot tell that a forwarded prop's effect gets overridden deeper in the composition, hence PARTLY. |
| Invalid HTML content model in emitted markup | [#2384](https://github.com/unovue/reka-ui/issues/2384), [#1597](https://github.com/unovue/reka-ui/issues/1597) | Checkbox inside a form renders "a visually hidden input" of type checkbox inside the `button` root; "an `input` element is only allowed inside a `button` when the `type` is set to `hidden`" (#2384). RadioGroup puts `input`s inside `button`s, so axe reports "Interactive controls must not be nested" (#1597). | YES | The HTML content model: which element kinds a `button` may contain, and that interactive elements may not nest. Both facts are static; the emitted tree is visible to the compiler. |
| `aria-hidden` applied to focusable or announced elements | [#2776](https://github.com/unovue/reka-ui/issues/2776), [#2163](https://github.com/unovue/reka-ui/issues/2163), [#1280](https://github.com/unovue/reka-ui/issues/1280), [#2324](https://github.com/unovue/reka-ui/issues/2324) | Toast focus sentinels render as `<span aria-hidden="true" tabindex="0">`: "`feature="focusable"` is inherently contradictory here: the element is visually hidden **and** focusable (`tabindex="0"`) **and** `aria-hidden`" (#2776); `VisuallyHidden` sets `aria-hidden` although its documented purpose is preserving content for assistive technology (#2163); Combobox focus triggers Chrome's "Blocked aria-hidden on a `<input>` element" warning (#1280); modal dropdowns hide the page but leave focusable items inside the hidden subtree (#2324). | PARTLY | That an ancestor carrying static `aria-hidden` must not contain a descendant with static positive `tabindex`. Fully static cases compile-time check; the modal case hides siblings dynamically, hence PARTLY. |
| Model-value type does not match the runtime value domain | [#2811](https://github.com/unovue/reka-ui/issues/2811), [#1308](https://github.com/unovue/reka-ui/issues/1308), [#2804](https://github.com/unovue/reka-ui/issues/2804), [#1641](https://github.com/unovue/reka-ui/issues/1641), [#1805](https://github.com/unovue/reka-ui/issues/1805) | Numeric pin input emits `undefined` into the array but "Current v-model type does not reflect this scenario" (#2811); Combobox `v-model` errors with `Type 'string' is not assignable to type 'string[]'` instead of inferring from the `multiple` prop (#1308); `currentElement` is typed non-nullable yet "Forwarding to `#text` or `#comment` ... -> `currentElement.value` is null, despite its `ComputedRef<HTMLElement>` type" (#2804); Calendar types force `as Ref<DateValue>` casts because the model type is wider than every concrete value (#1641); `boolean` left the `AcceptableValue` union, so `:value="true"` fails to typecheck although it works (#1805). | YES | The exact runtime domain of each prop and emit: pin slots hold `number \| undefined`; `multiple` selects the `T[]` arm of `v-model`; a forwarded ref resolves to `HTMLElement \| null`; item values include booleans. A compiler checking written types against produced values flags each mismatch at compile time. |
| Host type checker rejects valid usage | [#2769](https://github.com/unovue/reka-ui/issues/2769), [#2875](https://github.com/unovue/reka-ui/issues/2875) | `vue-tsc` reports "Type instantiation is excessively deep and possibly infinite." on ordinary `useForwardPropsEmits` forwarding (#2769); under Vue's `strictTemplates`, writing `aria-label` on `NavigationMenuRoot` is a type error (#2875). The defect sits in the library's own type definitions, not in user code. | PARTLY | Only partly reachable: a compiler that instantiates its own exported component types against representative call sites at library build time would surface both failures before release, but the fix is redesigning the types, not catching user mistakes. |
| Stale ref read at unmount leaks entries into a shared registry | [#2873](https://github.com/unovue/reka-ui/issues/2873) | `DismissableLayerBranch` adds `currentElement.value` on mount and deletes `currentElement.value` in `onUnmounted`, but "by the time `onUnmounted` runs, Vue has already unset the ref backing `currentElement`", so the delete misses and "every `DismissableLayerBranch` instance that unmounts leaks its DOM node". Issue #2778 fixed the identical shape in `StepperTrigger`. | YES | Ref lifetime phases: a forwarded-element ref reads non-null only between mount and before-unmount, so any read in `onUnmounted` must use a value captured earlier. A compiler that tracks validity per lifecycle phase rejects the second read outright. |
| Hidden content keeps rendering: leaks, flashes, and wasted work around presence handoff | [#1985](https://github.com/unovue/reka-ui/issues/1985), [#2767](https://github.com/unovue/reka-ui/issues/2767), [#2160](https://github.com/unovue/reka-ui/issues/2160), [#2227](https://github.com/unovue/reka-ui/issues/2227), [#920](https://github.com/unovue/reka-ui/issues/920), [#786](https://github.com/unovue/reka-ui/issues/786), [#1974](https://github.com/unovue/reka-ui/issues/1974) | `SelectContent` writes all options "to a fragment even when not visible", wrecking performance (#1985); during the popper-to-fragment handoff `optionsSet` empties for one frame, so the placeholder flashes (#2767, #2160); `forceMount` on ComboboxContent accumulates detached views in memory (#2227); a splice replaying the open animation (#920); dialog open triggers a layout reflow on large DOM trees (#786); devtools lag from popover components (#1974). | PARTLY | That a conditional subtree toggles between two mount sites while its instances persist, and that state held only by mounted DOM must survive the handoff; the compiler can force authors to declare persistence and can defer rendering of provably unread output. Frame-level flash and leak detection still need runtime checks, hence PARTLY. |
| Server/client divergence: hydration mismatch and environment guards | [#1845](https://github.com/unovue/reka-ui/issues/1845), [#2122](https://github.com/unovue/reka-ui/issues/2122), [#785](https://github.com/unovue/reka-ui/issues/785) | Tabs ids differ between server and client: "rendered on server: `id="reka-tabs-v-0-0-10-0-trigger-overview"` / expected on client: `id="reka-tabs-v-0-0-1-0-..."`" (#1845); the `useId` fallback compiles only on Vue 3.5+, so builds fail on 3.4 despite a runtime check (#2122); a Tooltip jumps to the screen corner after KeepAlive navigation (#785). | PARTLY | That generated identifiers derive only from stable, position-based sources shared by both render passes, and that feature-detection branches must not reference symbols absent from the declared minimum dependency version. Actual hydration comparison stays a runtime check. |
| Inline style output violates strict CSP | [#1229](https://github.com/unovue/reka-ui/issues/1229), [#2732](https://github.com/unovue/reka-ui/issues/2732) | Static inline styles in `VisuallyHidden` break `style-src` without a hash (#1229); dynamic positioning styles are worse: "nonces and hashes apply to `<style>`/`<link>` **elements only — never to inline `style` attributes**", so strict policies misposition every floating surface (#2732). | NO | The applicable CSP is a deployment-time fact unknown to the template. A compiler could emit stylesheet rules instead of style attributes everywhere, but nothing in the template tells it that the policy demands it. |
| `data-state` vocabulary collision across composed components | [#2823](https://github.com/unovue/reka-ui/issues/2823), [#1407](https://github.com/unovue/reka-ui/issues/1407) | `data-state` "currently speaks **seven vocabularies**": `open/closed`, `checked/unchecked`, `on/off`, `active/inactive`, `visible/hidden`, `expanded/collapsed`, plus an asymmetric emitter that leaves the negative value undefined (#2823). Composing a Tooltip on a ToggleGroupItem collides: "the data-state attribute is not being set correctly" because both write the same attribute on one element with different meanings (#1407). | YES | That each component part declares a closed vocabulary for every `data-*` attribute it emits, and that two parts rendered onto one element must not declare overlapping attribute names with disjoint vocabularies. The collision is fully static. |
