# std/i18n.vyrn

Lines: 1614. Exports: 1 (`export gen fn i18n`, line 1027; the module also exports nothing else — every other helper is a private `gen fn`/`fn`). Read at commit 82234d6a01922072cd24c289cf49ed7c2d592c09.

## What this module is for

A caller writes one `import * as t from i18n("./locales")` and gets a synthesized translation module at compile time: `i18n(dir)` reads every `<locale>.json` under `dir` (sandboxed, cached), flattens nested JSON keys with dots, checks cross-locale key and argument-signature drift, compiles each ICU message (plain text, `{name}`, `{n, plural, …}`, `{k, select, …}`) into ordinary Vyrn function bodies, and returns the module source — one typed function per key, a `Locale` enum with `setLocale`/`locale` state, a `TransKey` finite string type, `t()`, and `transKey()`. The compiler knows nothing about i18n. In-repo callers: `examples/i18ndemo.vyrn`, `examples/shelf/server/view.vyrn`, `examples/shelf/client/boot.vyrn`, and the site app pages under `site`.

## Findings

### 2. Algorithm complexity — MEDIUM

What: generation cost grows superlinearly in key count and hard-fails at the generator step budget near 200 keys per locale.
Where: `std/i18n.vyrn:972-1004` (key-collision check: a nested pair loop over all keys, calling `keyFnName` → `splitDot` + per-segment concatenation on both keys of every pair, O(K²·L) in keys K and key length L) and `std/i18n.vyrn:1106-1129` (drift check scans each locale's key array linearly via `includes` for every base key, O(locales·K²)); `std/i18n.vyrn:292` adds a linear `entryIndex` scan inside later loops.
Evidence: uncached wall time of `compiler/target/release/vyrn.exe emit-gen <driver>` on generated fixtures (2 locales en+uk): 276 ms @25 keys, 736 ms @50, 2445 ms @100, 5941 ms @150, 8530 ms @175 — and @200 the run fails with `generator i18n("./loc200") failed: generator exceeded its step budget` against `GEN_FUEL = 20_000_000` statements (compiler/vyrn-frontend/src/loader.rs:1485). Fixture drivers under `C:/Users/demko/AppData/Local/Temp/claude/ox-a2/i18n/`.
Cost if unfixed: any project whose translation table reaches a few hundred keys cannot build at all; today's in-repo locales stay at 22–24 keys (`examples/shelf/strings/en.json`, `examples/bin/strings/en.json`), so nobody pays heavily yet.
Smallest fix: hoist `keyFnName`/`keyPlainName` out of the pair loop into a precomputed array and replace the `includes` drift scans with a sorted merge or an index map. RECOMMENDATION, NOT A DECISION.

### 8. Allocation frequency — LOW

What: every emitted-code builder accumulates output with `out = out + chunk`, copying the whole prefix once per append.
Where: `std/i18n.vyrn:794` (`compileBody`), `std/i18n.vyrn:891-901` (`emitChain`), `std/i18n.vyrn:1220-1240` (`buildModule`).
Evidence: same measured curve as finding 2 — generation time quadruples from 100 to 175 keys (2445 ms to 8530 ms) while output size only grows 1.77x, which matches prefix-copy accumulation, not linear work.
Cost if unfixed: compile-time CPU per keystroke that touches a locale file; paid by every caller during builds.
Smallest fix: none available inside v1 if Vyrn strings are immutable — batch the collision check's repeated `keyFnName` calls instead (see finding 2). RECOMMENDATION, NOT A DECISION.

### 15. Best/worst case — LOW

What: the generated `t()` and `transKey()` are sequential if-chains over all K keys, so every runtime lookup pays O(K) string comparisons in the worst case.
Where: `std/i18n.vyrn:1421-1441` (`buildT` emits one `if key == …` per entry) and `std/i18n.vyrn:1290-1294` (`buildTransKey` likewise).
Evidence: native bench of generated modules (`compiler/target/release/vyrn.exe bench C:/Users/demko/AppData/Local/Temp/claude/ox-a2/i18n/b50.vyrn` and `b175.vyrn`): transKey hit median 274 ns @50 keys vs 918 ns @175 keys (linear); miss 58 ns vs 180 ns.
Cost if unfixed: `examples/shelf/client/boot.vyrn:9` calls `t`/`transKey` on every render; at shelf's 24 keys this is nanoseconds, but the cost scales linearly with each key added.
Smallest fix: emit a `match` over a hashed or length-partitioned dispatch instead of an if-chain. RECOMMENDATION, NOT A DECISION.

### 21. Footprint size — LOW

What: the synthesized module carries three exported-or-private functions per key plus one private helper per locale per key, so source size grows as keys × locales.
Where: `std/i18n.vyrn:1366-1397` (`buildKeyFns` emits a per-locale helper, a dispatcher, and an un-prefixed alias for every key).
Evidence: emitted module sizes measured from the `emit-gen` runs in finding 2: 48,020 B @50 keys ×2 locales, 144,117 B @150, 169,079 B @175 — against the 4 MiB `GEN_MAX_OUTPUT` cap (compiler/vyrn-frontend/src/loader.rs:1486).
Cost if unfixed: large locale sets bloat compiled binaries with duplicated dispatcher bodies that the alias layer doubles again.
Smallest fix: emit the alias as a thin forwarder only when a namespace import exists, or drop it and let namespace imports use the plain name directly. RECOMMENDATION, NOT A DECISION.

### 20. Thread safety — LOW

What: the generated module owns one process-global mutable `currentLocale`, so `setLocale` re-locales every later lookup in the whole program, not just the caller's session.
Where: `std/i18n.vyrn:1226-1228` (emits `let mut currentLocale` plus `setLocale`/`locale`).
Evidence: NOT MEASURED for concurrent interleaving; the sharing itself is visible in the emitted text (`let mut currentLocale: Locale = En` at module top level). `examples/shelf/server/view.vyrn:7` imports `setLocale` for a server-rendered page, so two simultaneous requests can render each other's locale.
Cost if unfixed: a multi-user server flips languages for all users whenever one user switches.
Smallest fix: thread the locale through an explicit parameter (or a request-scoped handle) instead of module state. RECOMMENDATION, NOT A DECISION.
