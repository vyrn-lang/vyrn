#### A map removal is a removal row (2026-09-25, `m7-mapcall`)
RFC-0125, milestone M7.
Decision: the lead's. The track takes `@remove`, the map builtin m7-lets left with no row. `@remove` joins `Spec::Removes`, the kind `@pop` and `@swapRemove` already have: a receiver the call shrinks in its own storage. The core already put `@remove` in a move-out window as a removal (`removal`). The entry's key and value are the map's, not names. The kernel judges the receiver as `modify` and the key as `read`, as it did for the Reserved call, so its answer cannot move. The releases and the shift are one `Fn_::map_remove` on `map_find`. The arm's `map_method` and `core_remove` both call it.
Count, on `b48fc67b` with the screen instrument: no refused body is held by `@remove` alone. `intkeys` `main` is also held by `@tally`, `mapdemo` `main` by a `Store/Key` of a `where`-checked value, and `mapkey` `main` by `@tally`, `Store/Key`, a key read and `Switch`. `@tally` alone holds `intkeys` `countRolling`, `knucleotide` `countKmers` and `wirekey` `main`, and with `@tallyBytes` it holds `tallybytes` `main`. `fieldmut` `main` is held by a map literal's `Let/Make`.
Went: the arm's `owns` flag, which was true on the only path that read it. Stayed: `@tally` and `@tallyBytes`, with no row.
Lines: `direct.rs` 21,865 to 21,895, because `map_remove` is a new function and the arm's `@has` keeps its `found` local so its bytes stay the same. `core.rs` 9,223 to 9,225. Refusals: 0 lost / 0 gained. Manifest: 2 rows, `intkeys` and `mapkey`.

Findings:
- A removal from a map held in a record field leaks on main `c2f59d6f` and at the tip, and the leak does not depend on this slice. `let mut h = H { n: 1, m: names() }` then `h.m.remove("a")`, with the map empty, reports "1 block(s), 16 bytes, never freed". With one entry it reports 4 blocks, 112 bytes. A local map and an `Array` field's `pop` do not leak.
- The corpus's `@remove` sites are all interpolated or bound by `let`, so the row moves no whole body. Its effect is per statement: 2 manifest rows.
Left: `@tally` and `@tallyBytes`, which have no row. A map rebuild row moves `countRolling`, `countKmers` and `wirekey` `main` alone, and `intkeys` `main` with this slice. The field-removal leak above has no track.
