# std/i18n

Typed translations as a generator library.

  import { i18n } from "std/i18n"
  import { t, setLocale, locale, Locale, TransKey, tCartItems } from i18n("./locales")

`i18n(dir)` reads every `<locale>.json` under `dir` at compile time, checks
that the locales agree, compiles each message to a Vyrn function body
and returns the module as `Code` (`vyrn emit-gen <file>` shows it). The
module holds `Locale` (one variant per file), `setLocale`/`locale`,
`TransKey` (the finite type of every dotted key), one function per key with
arguments taken from the message and the base-locale message as its doc,
`t(key)`, and `transKey(s)`, which checks a runtime `String` against the
key set.

`catalogue(dir)` reads the same files and writes only one exported function per
key and locale, `tCartItems__En`. It holds no `Locale` and no module state, so a
generator can call it at generation, naming its locale, and two catalogues link in
one program, where two `En` variants would clash.

A message is Unicode MessageFormat 2, read by `std/i18n.syntax`: text, where
a backslash escapes `\`, `{`, `|` and `}`; a placeholder `{$name}` (String);
`.input` and `.local` declarations; and one `.match` selector with a `*`
variant. `:number` makes an Int64, selected by an integer key, then by the
locale's plural category; `:string` selects a finite string type of its keys;
`:list` joins an `Array<String>` as the locale does. Markup, options,
attributes and other functions fail generation, as do numbers, booleans and
null in a locale file. An argument name may not start with `__`.

## i18n

```vyrn
fn i18n(dir: String) -> Code
```

Read every `<locale>.json` under `dir`, check the locales, and return the
translation module.

## catalogue

```vyrn
fn catalogue(dir: String) -> Code
```

Read every `<locale>.json` under `dir`, check the locales, and return one exported
function per key and locale, each of which reads no module state.
