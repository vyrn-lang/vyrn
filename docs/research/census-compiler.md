# Census: compiler mechanisms that outlived their base decision

A read-only census of Vyrn's compiler at `3ac6d54`, over
`compiler/vyrn-frontend/src/`, `compiler/vyrn-codegen/src/` and
`compiler/vyrn-cli/src/`. Nothing was fixed.

The test applied is not "is this wrong". It is: **the mechanism is correct,
and it should not exist** — something was built to cope with a condition the
author had the authority to remove. A parser that recovers what its caller
already held. A string used as an identity. A closed set the compiler owns
where the vocabulary is open. One rule written N times. A guard that cannot
guard.

Findings already recorded elsewhere are not re-derived here: the five-lens
audit (`audit-linus-to-agda.md`), the codegen review (`review-codegen.md`, at
`52e462f`) and the loader review (`review-loader.md`, with its ~60-site
hardcoding census) own their findings, including `from_rendered` (since
deleted, PR #177), the mangle collision (#165), the `"generated by X at Y"`
module key, the builtin-name lists (RFC-0094), the trap-wording duplicates,
`wasm.rs`'s IR-parsing boundary (a defended decision), and the `Audience`,
scheme, target and log-level literals. What follows is new.

Every finding cites `file:line` and states three things: what the mechanism
is, what base change would delete it, and what that change costs. **CONFIRMED**
means a program was run or the shape is unambiguous in the code; **PLAUSIBLE**
means argued from reading. Where the design record argues the decision, the
entry says "design critique", not "defect".

## 1. Round-trips: a consumer parses what a producer held structurally

### 1.1 CONFIRMED — High. The checker's answers are computed, validated, and thrown away

`checker.rs:3446` (`fn expr`) returns `Result<Type, Diagnostic>` — the checker
derives the static type of **every expression in the program**, and the
substitution of every generic call, with full error checking. It writes none
of it down. The checker borrows the `Program` (`&self`, `&Program`), so it
could not annotate the AST if it wanted to, and no side table exists.

So every downstream engine re-derives the same answers, each with its own
code:

- **The direct wasm backend has a second expression typer.**
  `direct.rs:4682` `fn peek(&mut self, e: &Expr, line) -> Result<Type, String>`
  is 510 lines (to `direct.rs:5192`), called from 53 sites, plus its
  satellites `peek_arm` (`direct.rs:4550`), `peek_ho` (`direct.rs:7613`),
  `gen_peek` (`direct.rs:5641`), `match_ty`/`join` (`direct.rs:4525, 4567` —
  the checker's match-arm type join, re-run at lowering time).
- **The textual backend re-derives types by threading.** Every `gen_*`
  emitter returns `(String, Type)`; `static_ty` (`lib.rs:3973`) answers the
  cases where a type is needed before emission. The re-derivation is not one
  function but a convention distributed over ~300 functions.
- **Both backends re-run generic instantiation solving.** `solve_param`
  (`lib.rs:12316`) is documented as: "Mirrors the checker's `unify`, minus
  error checks (the checker already validated the call)" (`lib.rs:12303`).
  Both backends call it at every generic call site; the checker solved the
  same call to validate it.
- **Both backends re-derive contextual typing.** `expected_fn_sig`,
  `fn_arg_param_types` and `resolve_fn_arg` exist twice (`lib.rs:7867, 7349,
  7368`; `direct.rs:7854, 7697, 7477`), and each backend maintains its own
  `expect: Vec<Type>` stack — `direct.rs`'s field comment says "Same mechanism
  the LLVM emitter uses, for the same reason".
- **The ownership passes have a fourth copy.** `declared.rs:98-120`
  (`Declared::type_of`) re-derives expression types for `own`/`movecheck`,
  and its own doc records the drift this already caused: "the two forks had
  drifted: the list said `@push` returns `Array<Unit>` and the row says
  `Array<T>`" (`declared.rs:105`). The interpreter carries a fifth partial
  copy, `interp.rs:6532` `type_of`.

**What the mechanism is.** Four-plus independent re-derivations of answers the
checker already computed, each "minus error checks", each free to disagree
with the checker and with each other.

**What base change would delete it.** Record the checker's answers: node ids
on `Expr` (or the node-address side table the backends already use for
`own::analyze`'s rows — `lib.rs:4546` "Node-address identity — must match
`vyrn_frontend::own`"), with a `NodeId -> Type` map and a per-call-site
substitution map, produced once by the checker and read by the interpreter,
both backends, `own`, and `movecheck`.

**What it costs.** Node identity through the parser and through every
synthesizer of AST (the loader's injected modules, `jsonenc`/`jsondec`,
generators) — the same invariant the node-address keys already impose
informally, made explicit. This is the largest single change named in this
census, and the one with the largest yield: finding 5.1 argues that the
re-derivations are where the cross-backend bugs live.

### 1.2 Design critique (CONFIRMED shape) — Medium. Synthesized codecs print types into source and parse them back

`jsonenc.rs:68` and `jsondec.rs:86` (`fn spell`) render a `Type` the compiler
holds structurally with `Display`, splice the spelling into generated Vyrn
source, and hand the text to the lexer and parser to rebuild the AST the
compiler already had. The module argues the decision openly — `jsonenc.rs:17`:
"**Why it generates source text** — Because the parser is a perfectly good
AST builder." That argument is real: the generated module gets checking,
diagnostics and all three engines for free.

What the argument does not cover is the inverse obligation it creates:
`Display` must now be an exact parser inverse, and it is not one —
`jsonenc.rs:128`: "An ANONYMOUS enum has no source spelling (`Display`
renders `enum { A | B }`, which is not a type the parser accepts)." A class
of types is unencodable for a **printing** reason, not a semantic one. The
same module demonstrates the alternative in its own file: predicates are
"built as AST rather than as source" (`jsondec.rs:140`).

**Base change.** Build the codec functions as AST (the module already does it
for predicates), or give `Display` a tested round-trip property. **Cost.**
Mechanical; the AST constructors are all public within the crate.

### 1.3 CONFIRMED — Medium. `code_quote` re-parses fabricated source to learn what its own parse just knew

`parser.rs:4789-4884`. A `vyrn"…"` quote is validated by building a skeleton
with `__vyrn_hole{i}` placeholders and parsing it (in up to four grammar
modes — declaration list, statement list, expression, type). Then, **per
hole**, `hole_context` (`parser.rs:4857`) builds the whole skeleton again with
`"__vyrn_probe__"` substituted for that hole and re-lexes + re-parses it in up
to four modes again, to decide whether the hole sat in expression or
identifier position.

The information being probed for — "which production consumed this
placeholder" — existed inside the skeleton parse that already ran. The parser
was standing on the answer and did not record it.

Two accumulated costs mark the mechanism's age:

- The doc at `parser.rs:4786` says the flag is "(`0` = expression, `1` =
  identifier)"; `hole_context` returns three values (`0`/`1`/`2`,
  `parser.rs:4865, 4880, 4882`). The fuller legend exists only on the helper.
- The placeholder is a spellable identifier: a quote whose literal text
  itself mentions `__vyrn_hole0` collides with hole 0's placeholder in the
  skeleton and probes.

**Base change.** Record the syntactic role of each `__vyrn_holeN` token as
the sub-parse consumes it (a small side channel on the sub-parser), and
delete `hole_context`. **Cost.** A field on the sub-parser and one line at
each place a placeholder identifier is consumed; the probe machinery
(~40 lines and O(holes × modes) re-parses per quote) goes away.

### 1.4 CONFIRMED — Medium. Two numbers round-trip through the SSE prologue slot

`main.rs:4438-4441`, in `pump_socket`:

```rust
// `closeCode` and `maxFrame`, in the slot SSE uses for its prologue.
let mut nums = head.body.split_whitespace();
let mut close_code: u16 = nums.next().and_then(|s| s.parse().ok()).unwrap_or(1000);
let max_frame: usize = nums.next().and_then(|s| s.parse().ok()).unwrap_or(0);
```

`std/http` (the producer) holds the WebSocket close code and fragment limit
as numbers, joins them into a string, and stores the string in
`ServeResponse.body` — a field whose meaning for this response kind is "the
prologue slot SSE happens to use". The CLI recovers the numbers by splitting
and parsing, and a producer that mis-writes the pair does not error: it
silently closes with 1000 and an unbounded frame size.

**Base change.** Two typed fields on `interp::ServeResponse` — the struct is
this repo's and already carries `status`, `content_type`, `vary`, `headers`.
**Cost.** One struct change and the two ends of one seam; the overloading of
`body` and both `unwrap_or` defaults disappear.

### 1.5 CONFIRMED — Medium. Route rows are comment prose, and the reader knows it

`main.rs:1038-1053`, in `routes_cmd`. The `std/ui` generator writes each
route into the module it emits as a `//@route METHOD PATH PROC FILE` comment
line. The CLI reads them back with `strip_prefix("//@route ")` and
`split_whitespace()`, and — because a generator copies component text through
verbatim — must first compute a lexer comment-mask
(`origin::comment_lines`, `main.rs:1043`) to tell a real directive from a
string literal that merely looks like one. The comment above the loop counts
itself: "The third scan over generated text".

The structured channel already exists **in the same function**: the symbol
map (`symbolmap::read`) is consumed a hundred lines below. A route whose path
or procedure contains a space is silently dropped by the `f.len() < 4` guard.

**Base change.** Put route rows on the symbol map (or any structured export
of the generated module) and delete the prose scan and its comment-mask.
**Cost.** One generator-side emit change plus one reader; the third scan and
its masking machinery go away. (The `//@origin`/`//@diag` directive family
is the loader review's finding; this entry is only the route table, which has
a structured sibling channel already in use.)

### 1.6 PLAUSIBLE — Low. A trap message is stripped by matching the synthesized module's filename

`main.rs:1847-1850`, in `from_json_cmd`: the CLI runs an embedded converter
program under the interpreter and, on failure, strips the trap's position with
`.split_once(" (from-json.vyrn:")` — prose surgery keyed on the synthetic
module's name, needed because an interpreter trap is a `String` with the
position baked into the sentence. Small, but the same base decision as the
deleted `from_rendered`: positions ride in prose, so consumers do prose
surgery. **Base change.** A structured trap (message + location) from
`run_with_args`. **Cost.** One error type on one API.

## 2. One rule written N times

### 2.1 CONFIRMED — High. The `.vyx` section rule exists three times, and a naive copy lies

The rule "where does a `.vyx` component's `<script>` section end" is decided:

1. **Correctly**, in `std/vyx.vyrn` — a comment/string-aware scanner. Its doc
   states the exact hostile case: "found by a scanner that knows the
   section's own language, so a literal `</script>` inside a helper string
   never truncates the section (RFC-0039 §2)" (`std/vyx.vyrn:1044`), with a
   regression test. The repo even pins the lexer half of the fact in a unit
   test: `interp.rs:7694` asserts `"</script>"` inside a string is one string
   token, not markup.
2. **Naively**, in `vyrn-cli/src/main.rs:1596-1602` (`vyx_script_body`):
   `text.find("<script")` … `text[start..].find("</script>")`. Feeds
   `vyrn why`'s import graph (`main.rs:1426`) and `why --contract`.
3. **Naively**, in `vyrn-frontend/src/contracts.rs:698-704` (`has_template`):
   the same two `find` calls — under a doc comment that claims the property
   the code does not have: "searched OUTSIDE the `<script>` — a template tag
   inside a script string is not one."

**Reproduction** (run against `compiler/target/release/vyrn.exe`). A minimal
project: `vyrn.json` (`main: main.vyrn`), `util.vyrn` exporting `helper`,
and `widget.vyx`:

```
<script>
import { helper } from "./util"

fn label() -> String {
    return "ok"
}
</script>
<template><p>{label()}{helper()}</p></template>
```

```
$ vyrn why util.vyrn
  imported by:
    widget.vyx -> util.vyrn
```

Change one string: `return "</script>"`.

```
$ vyrn why util.vyrn
  imported by: nothing in this project reaches it
```

The truncated body ends mid-string-literal, the lexer refuses it,
`project_imports` drops every edge from the component without a word (the
`continue` at `main.rs:1430`), and `why` reports a false negative about a
program that compiles and runs — `std/vyx`'s scanner handles the same file
correctly.

**Base change.** One string-aware section splitter, owned in one place, that
both Rust consumers call — the lexer already knows how to walk a Vyrn string,
and `origin::comment_lines` shows the frontend already exports lexer-shaped
masks for text scanning. **Cost.** One ~50-line function in `vyrn-frontend`
and two call-site edits; both naive copies and the false `has_template`
comment go away.

### 2.2 CONFIRMED — Medium. A second JSON escaper, incomplete, on the schema path

`types.rs:953-965` (`json_escape`) escapes `"` `\` `\n` `\t` and passes
everything else through. `codec.rs:357-369` (`escape_into`), in the same
crate, is the complete table: those four plus `\r` and `\u00XX` for the other
control bytes, under the note "Both backends must produce these exact bytes."

`types.rs:879` feeds a raw user regex through the incomplete one:
`json_escape(&format!("^{pat}$"))`.

**Reproduction.**

```vyrn
type T = String where value =~ "a\rb"

fn main() -> Int64 {
    print(jsonSchema(T))
    return 0
}
```

```
$ vyrn run cr.vyrn > out.json
$ xxd out.json | grep -o '5e 61 0d 62'   # "^a<CR>b" — raw 0x0D in a JSON string
```

Recorded output bytes: `22-70-61-74-74-65-72-6E-22-3A-22-5E-61-0D-62-24-22`
(`"pattern":"^a<0x0D>b$"`). RFC 8259 forbids an unescaped control character in
a string, and the repo's own strict reader (`codec.rs:272`,
`Some(c) if *c < 0x20 => return Err(..)`) refuses to read the document
`jsonSchema` emitted.

**Base change.** Delete `types::json_escape`; call `codec::escape_into`.
**Cost.** One import; the incomplete table cannot drift because it no longer
exists.

### 2.3 PLAUSIBLE — Medium. Four matches over `Type` answer one wire question

The question "can this type cross the JSON wire, and as what" is answered
independently by `codec.rs:460` (`codable` — the checker's gate),
`types.rs:612` (`type_schema` — the schema emitter), `jsonenc.rs:169` (the
encoder synthesizer) and `jsondec.rs:224` (the decoder synthesizer). Three of
the four have an open `_` arm, so a new `Type` variant can be admitted by one
and unknown to the others without any compile-time complaint.

The drift is already observable in the code for `Lazy`: `codec.rs:552`
approves encoding a lazy value (`if decode { Err } else { codable(inner) }`),
while `type_schema` has no `Lazy` arm at all (falls to `{}` — "any"), and
`jsonenc` dispatches on `types::resolve`, which rewrites `Lazy` into a
`Type::Fn` (`types.rs:1466`) — the error arm. Three answers to one question.
Ranked PLAUSIBLE because no program was run to force the three answers apart.

**Base change.** One table keyed by `Type` that yields the gate verdict, the
schema fragment, and the encoder/decoder shapes together — the same
consolidation `prelude.rs` records as its own purpose for builtin names
("Four lists, one fact each, and every one complete only while somebody
remembered to extend it", `prelude.rs:8`). **Cost.** A refactor of four
matches into one; the RFC-0094 precedent shows the shape.

### 2.4 CONFIRMED — Medium. The extern trap stub is a third copy of two owned facts

`main.rs:2889-2894` (`extern_trap_stubs`) writes, by hand:

```rust
"void __vyrn_extern_{name}(void) {{ fputs(\"error: extern `{name}` is not available on this target\\n\", stderr); exit(1); }}"
```

Two facts, both owned elsewhere: the import symbol scheme
(`vyrn-codegen/src/lib.rs:594` `extern_symbol`, private — the CLI's comment
admits the coupling: "`__vyrn_extern_<name>`, matching codegen") and the trap
wording (`interp.rs:2644`, asserted byte-identical by `tests/parity.rs:215`).
The sibling fact one screen up is already exported the right way:
`host_boundary_extern` (`lib.rs:651`) is `pub` precisely so the CLI does not
respell it.

**Base change.** Make `extern_symbol` public and export the wording (or the
whole stub) from the crate that owns it. **Cost.** Two `pub`s.

### 2.5 CONFIRMED — Low. The bench report hand-copies the build description it stands beside

`main.rs:3238-3239`: the `--json` bench harness is synthesized with
`Expr::Str("native".to_string())` and `Expr::Str("O2".to_string())` as its
target/opt fields — while fifty lines below (`main.rs:3292`)
`native_target_for` picks the real target (`v1`…`v4`/`native`) and
`add_native_clang_flags` (`main.rs:230`) owns the real flags. A `--native-target v3`
bench run emits a machine-readable report labelled `native`. This is the same
drift `add_native_clang_flags`'s own doc records having ended once before
(the `-O2` that "only `bench_native` passed").

**Base change.** Pass `target.march()` and the flag list from the one owner
into the harness, or drop the two fields. **Cost.** Two arguments.

### 2.6 CONFIRMED — Low. The desugared temp-name vocabulary is one set, spelled at four sites, filtered by two predicates

`ast.rs:123-134` documents the closed set of magic name suffixes the desugars
use; the actual spellings live at the call sites — `[]idx` (`parser.rs:986`,
`3807`), `[]val` (`parser.rs:3813`), `[]arg{n}` (`parser.rs:1103`). The doc's
own text spells two of them differently ("`[]i`, `[]v`"), and it records that
a second consumer already matches by a **different** predicate: "`symbols.rs`
filters all of them out of the completion index on the looser
`contains('[')`". One vocabulary, four producers, two predicates, and the
only registry is a comment.

**Base change.** A `TempKind` field on the synthesized `Stmt::Let` instead of
a suffix convention inside the name `String`. **Cost.** One enum and the four
producer sites; both string predicates become field tests.

### 2.7 PLAUSIBLE / design critique — Low. Two JSON parsers in one crate, because numbers were `f64` first

`schema.rs:68` (`parse_json` → `Json`, numbers as `f64`) and `codec.rs:107`
(`parse` → `JsonV`, exact integers) are two full recursive-descent JSON
parsers with two enums, two escape decoders and two error vocabularies.
`codec.rs:9` records the relation ("a sibling of the order-preserving parser
in `crate::schema`") and the reason is the known manifest finding: `Json`
holds every number as `f64`, so when the wire codec needed exact `Int64`s, a
sibling parser was built instead of fixing the number representation. The
coping mechanism is correct; the base it copes with is the recorded `f64`
defect. One concrete asymmetry: only `schema.rs` carries the recursion bound
(`MAX_JSON_DEPTH`, `schema.rs:66`); `codec.rs`'s `value` recurses unbounded
on run-time input.

**Base change.** One parser with exact numbers; the `f64` view becomes a
projection. **Cost.** The manifest reader's number semantics change — which
is the already-filed `1e30` finding's fix, not a new cost.

## 3. Strings used as identities

### 3.1 CONFIRMED — Medium. Wire-codec identity is a truncated hash of a `Debug` string, twice

`jsonenc.rs:56-58` and `jsondec.rs:62-64` are byte-identical:

```rust
fn type_key(ty: &Type) -> String {
    crate::hash::sha256_hex(format!("{ty:?}").as_bytes())[..16].to_string()
}
```

The identity of a synthesized encoder/decoder is the **derived `Debug`
rendering** of `Type`, hashed and truncated to 64 bits. The doc claims
"Injective by construction, unlike a readable mangle" (`jsondec.rs:58`) —
citing the exact collision class (#165 / RFC-0077 M2e) this mechanism
re-introduces at a lower rate: any `Debug`-affecting edit to `Type` silently
renames every codec symbol (a cache/reproducibility hazard the codegen review
already flagged for `mangle_dispatch_sym`, `lib.rs:12451` — this is the same
decision taken twice more, in a second crate), and 64 bits is a birthday
bound, not a proof.

**Base change.** One `types::key(&Type)` — a real structural serialization,
written once, used by `jsonenc`, `jsondec` and `mangle_dispatch_sym`.
**Cost.** ~30 lines; three call sites.

### 3.2 PLAUSIBLE — Low. A `.` inside `Type::Named` means two different things

Producers: `parser.rs:2532` fabricates `format!("{name}.{fname}")` for
synthetic inline-refinement helper types; `parser.rs:5236` / `parser.rs:4355`
produce `ns.Type` / `ns.Variant` for namespace-qualified names (rewritten by
the loader, but present in the meantime). Consumer: `types.rs:645` decides
"is this a desugaring artifact" by `n.contains('.')`, and a third site
re-derives the convention by string reconstruction
(`schema_reflect.rs:498`, `if n == &format!("{parent}.{field}")`). Two
meanings share one spelling and the consumers distinguish them by punctuation.
No misbehaving program was built, so PLAUSIBLE — the exposure is that
schema emission for any dotted name silently inlines instead of `$defs`.

**Base change.** A `synthetic` marker on `TypeDecl` (or a distinct `Named`
variant), so the punctuation convention stops carrying meaning. **Cost.** One
field, three sites.

### 3.3 CONFIRMED — Low. A pipeline stage is a string, and `vyrn fix` filters on it

`diagnostics.rs:59` types the stage as `pub stage: &'static str`
(`"lex" | "parse" | "check" | "movecheck"` by comment), and
`main.rs:2407` selects fixable diagnostics with
`.filter(|d| d.stage == "movecheck" && d.file.is_none())`. All producers are
in-tree; a renamed stage makes `vyrn fix` silently apply zero fixes and exit
0. (The five-lens audit noted the `stage` string in passing under the deleted
`from_rendered`; the consumer that turns it into behavior is recorded here.)

**Base change.** `enum Stage` — four variants, all producers in one
workspace. **Cost.** Mechanical.

## 4. Sets and copies the compiler owns

### 4.1 CONFIRMED — Low. `schema_reflect` re-lexes every module to recover a column the lexer already produced

`schema_reflect.rs:59-82` builds its `Origins` index by re-running
`lexer::lex` over each module's full source and guessing: "the *first*
identifier token spelled like the declaration, on the declaration's line, is
its name" (`schema_reflect.rs:51`). The mechanism exists because the AST
records `line` and not `col` on declarations (`schema_reflect.rs:47` says
exactly this) — a base decision the diagnostics struct already outgrew
(`Diagnostic` carries `col`/`end_col`; declarations still do not).

**Base change.** A `col` on `Function`/`TypeDecl`, stamped by the parser,
which is holding the exact token when it builds the declaration. **Cost.**
One field, and the whole re-lex heuristic index deletes.

### 4.2 CONFIRMED — Low. The dev banner hand-lists a directory it serves whole, and has drifted

`main.rs:3900` prints
`dev:   /vyrn-runtime/ -> web runtimes (wasi-min.js, vyrn-rpc.js, vyrn-query.js)`
while the server serves everything under `web/` — which today also holds
`vyrn-dom.js` and `vyrn-nav.js` (verified against `web/`), the two runtime
files the examples actually import. The list drifted the way every
hand-written mirror of a directory does. **Base change.** Print the
directory, not an inventory of it.

### 4.3 CONFIRMED — Low. Two content tables the CLI owns over vocabularies it does not

- `main.rs:4277` `reason_phrase`: a 25-row match over HTTP status codes; any
  other status ships an empty reason. RFC 9110 makes the phrase optional —
  the honest base change is to emit none and delete the table.
- `main.rs:4005` `dev_content_type`: nine extensions over the user's
  `public/` directory; `.woff2`, `.webp`, `.svg`-adjacent assets fall to
  `application/octet-stream`. The directory's vocabulary is the project's,
  not the CLI's.

### 4.4 PLAUSIBLE — Low. Reflection renders "canonical source" through a diagnostic summarizer

`schema_reflect.rs:437` (`render_type_decl` — "lossless enough for a
generator to re-emit contract types verbatim") renders predicates through
`checker::pred_summary` (`checker.rs:8449`), whose documented job is "a terse
one-line rendering … for diagnostics" and which elides:
`Expr::Match{..} => "match { .. }"`, `Expr::ArrayLit{..} => "[..]"`
(`checker.rs:8494-8501`). A predicate of those shapes re-emits as source that
cannot parse. PLAUSIBLE: no generator was driven through the elision.
**Base change.** Keep the predicate's source span and re-emit the user's
bytes — `fmt.rs` proves the token stream is retained losslessly.

### 4.5 Design critiques recorded, not defects

- **`fmt.rs` is a second grammar by charter.** The formatter re-derives
  generic-vs-comparison `<`, unary `-`, lambda `|` from token adjacency
  (`fmt.rs:126-262`), with paired open/close lists it names as "the two ends
  of the same grammar" (`fmt.rs:195`). RFC-0017 chose a token-stream
  formatter with re-lex equality as the safety invariant; the two hand lists
  are that decision's standing cost, worth naming when the formatter next
  drifts.
- **`finite.rs` re-recognises the interpolation the parser desugared.**
  `finite.rs:25` argues it: "recognise the desugared chain … keeps this a
  pure analysis with zero parser churn." The already-known line-number loss
  (audit A5.5) is the same desugar's other cost; a retained
  `Expr::Template` node would delete both.
- **`checker.rs:978` is the third spelling of the served-`handle` shape.**
  The loader review's census caught the CLI and LSP copies; the checker's
  copy (`fn handle(req: Request) -> Response` by type **name**) makes it
  three sites for one RFC-0016 rule.

## 5. The shared-lowering question

The brief: how much of the two compiled backends is semantics that could be
decided once, versus genuinely target-specific instruction selection.

### The inventory

`lib.rs` is 15,833 lines / 330 functions; `direct.rs` is 15,745 / 232.
Twenty function names exist in both files as **independent implementations**:

`call`, `coerce`, `emit_validation`, `expected_fn_sig`, `f`,
`fn_arg_param_types`, `free_declared_boxes`, `free_snap`, `free_str_temp`,
`lookup`, `main`, `owns_heap`, `register_fnval`, `resolve`, `resolve_fn_arg`,
`show_dispatch`, `store_index`, `str_append_shadow`, `str_len`,
`stream_step_sig`.

Strike the incidental (`f`, `main`, `lookup`) and every remaining name is a
**semantic rule**, not an encoding: type re-derivation (five names, finding
1.1), release placement (four names), boundary coercion and validation (two),
protocol/show dispatch, closure registration, indexed stores, string append.

By section, `direct.rs` splits into: driver + extern ABI (~680 lines), types
and `Repr` (~550), **function lowering** (`direct.rs:1228-11937`, ~10,700 —
statements, expressions, calls, drops, sums, arrays, maps), instruction
helpers (~250), and the emitted runtime — allocator, float formatter, string
intrinsics (`direct.rs:12186` on, ~3,560). `lib.rs` has the same skeleton
with the LLVM prelude in place of the wasm runtime.

### The proportion

Read any duplicated pair and the split inside it is consistent. `coerce`
(`direct.rs:3726`, `lib.rs:2364`) is a decision ladder — does validation
apply (shared `validation_required`), which numeric crossing is this, in what
order, with the interpreter named as the tie-breaker in the comments ("that
is what the interpreter does", `direct.rs:3797`) — where each decision's
*emission* is one to four instructions. The ladder is the function; the
target vocabulary is its leaves. The same holds for the drop walks
(`emit_all_drops` / boundary walks), the builtin `call` dispatch (~52 arms in
each backend, known census), the match/if-let lowerings, the string-append
fast path.

The honest estimate: **of the ~10,700-line lowering core in each backend,
roughly two thirds is decision and one third is instruction emission; over
the whole file, on the order of 40-50% of each backend re-states semantics
that could be stated once** (~6-7k lines per backend). The irreducible
target-specific residue is real and large — the wasm shadow stack and
`Repr`, the segregated-free-list allocator, the 511-line float formatter, the
LLVM text plumbing and prelude, SSA temp management — but it is the smaller
half, and it is not where the bugs are.

### The evidence that the split matters

Every cross-backend defect in the recent record lived in the duplicated
half: region ownership routed at different places (#172 — "the arena's set is
the same set on both backends" touched `direct.rs` +160/`lib.rs` +11), the
match-arm payload handover (#166 — fixed in `own.rs`/`movecheck.rs` once,
then consumed twice: `lib.rs` +46, `direct.rs` +34), the map entry release
(#163 — `lib.rs` +115, `direct.rs` +95, `toolchain.rs` +10: three copies of
one rule), `place_owns` missing the region guard its twin `slot_owns` had
(review G2.2), and the trap wordings that agree byte-for-byte by parity's
grace (review G5.1).

Meanwhile the classes that are already shared have produced **zero** recorded
cross-backend bugs: `own.rs` fates and `owns_heap` (both backends are thin
wrappers over `vyrn_frontend::own::owns_heap` — `lib.rs:3046`,
`direct.rs:9708`, each with a comment saying the sharing is the point),
`llt_of`/`layout.rs`, `validation_message`, `IO_MESSAGES` (with
`io_message_parts` splitting the one string for the backend that cannot
format — `lib.rs:645` — instead of a second wording), `CALL_DEPTH_LIMIT`,
`solve_param` (shared between the two backends, `direct.rs` calls
`crate::solve_param` at 12 sites), `finite::string_flow_proven`, the
`codec.rs` Issue vocabulary, and the synthesized JSON codecs — one generated
definition all engines execute, "no engine has a JSON encoder of its own"
(`jsonenc.rs:73`). The codebase has already run the experiment in both
directions; the results are unanimous.

### The three-plus-one rules that most belong in a shared layer

1. **Expression typing and instantiation solving** (finding 1.1). The
   checker's discarded answers are the root duplication; recording them
   deletes `peek` (510 lines), the `(String, Type)` threading convention,
   both `expect` stacks, both copies of `expected_fn_sig` /
   `fn_arg_param_types` / `resolve_fn_arg`, and `declared::type_of`.
2. **Release placement.** `own.rs` already computes statement-level fates;
   what is duplicated is the *placement walk* — which exits release what, in
   what order, with which snaps (`free_snap`, `free_str_temp`,
   `free_declared_boxes`, `emit_all_drops`, the break/continue boundary
   walks). #158/#163/#166/#172 and the whole G2.x family are placement
   drift. A shared pass that lowers to explicit abstract release operations
   ("release slot X here"), which each backend merely encodes, removes the
   class.
3. **The trap table.** Half the parity-load-bearing strings are shared and
   half are hand-written twice (known); what this census adds is that the
   *conditions* are duplicated too — `lib.rs:6916` annotates its shift guard
   "(this exactly mirrors the interpreter's `y < 0 || y >= bits`)". One
   table of (condition-shape, wording), consumed like `IO_MESSAGES` already
   is, makes trap parity a property instead of a test outcome.
4. **The boundary ladder.** `coerce` + `emit_validation` — the order of
   validation, numeric resize, float crossing, reshape — is one rule
   duplicated with the interpreter as its informal referee. The leaves
   (instructions) stay per-backend; the ladder should not.

This is a sizing, not a design. But the direction of the existing seams —
`own.rs`, `solve_param`, `IO_MESSAGES`, the synthesized codecs — is uniform:
every rule moved into the frontend or into one shared table stopped producing
parity bugs, and no rule that stayed duplicated has stopped.
