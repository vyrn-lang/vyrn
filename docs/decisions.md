# Design decisions

Each line is a decision that binds the code today, with its reason. A line that
starts with "No" records a road not taken; reopen it only with the evidence its
reason asks for. A change that contradicts a line changes the line in the same
pull request.

## Language

### Scope

- A feature earns its place by helping most programmers every week. Macros, higher-kinded types, full dependent types and custom allocators stay out, so the core stays small and predictable.
- No class inheritance. Behaviour is shared through protocols and composition, because base classes are fragile and diamonds are ambiguous.
- No attributes. Where a rule over a declaration is not enough, name a type.
- No new keyword for a library domain (RPC, config files, i18n). A generator import is the mechanism; an `rpc` keyword was built and removed.
- No `async`/`await`, coroutines or blocking run loop. The host owns the event loop and calls exported handlers; wasm cannot suspend, and determinism is the product. Reopen when wasm stack switching ships broadly or handlers need an outbound HTTP client.
- No unwinding. A trap ends the process and runs no release path.

### Types

- Records are structural with width subtyping: a record with more fields is usable where fewer are expected. Types describe shape, not identity. Width applies at the top of a value only (`types::assignable`), because a wider record inside a container or a function type is read in place and would need a hidden copy of every element.
- A type argument counts for compatibility even where no field mentions it (`types::assignable`): two applications of one generic type fit only if their arguments are interchangeable. A brand such as `Handle<T>` in `std/slots` is then checked at compile time without a phantom field in its layout.
- A record's layout is a function of its field set: fields sit in descending alignment, then by name. Two record types with the same fields are then one representation everywhere, as an `Option` payload, an `Array` element or a `fn` result, and no flow converts between them. Laid out in declared order, each such flow read one field as another.
- A record that lands in a slot of a record type with fewer fields is rebuilt where it lands: the core takes the slot's fields and releases the rest (`vyrn_lower::core::Builder::fit`), so the extra fields are freed and no owned wider record reaches the emitter at a narrower slot. A borrowed crossing is the emitter's `Rung::Rebuild`, a copy that owns nothing.
- No casts and no `as` on values. A conversion is a call named after the target type, and integer arithmetic wraps at the type's width (`language.md`), so memory is never reinterpreted.
- The type transformers `Omit`, `Pick`, `Merge`, `Partial` and `A & B` are erased before lowering. `Readonly<T>` is `T`, because records are immutable.
- Every numeric type names its size (`Int8` to `Int64`, `UInt8` to `UInt64`, `Float32`, `Float64`). There is no unsized `Int` or `Float` and no implicit widening.
- Validation lives in the type (`type Age = Int64 where value >= 18`). A constant is proven at compile time at no cost, anything else is checked at every value boundary, and a raw value never becomes the refined type without construction.
- Branches of different validated scalar types over one base join to their union (`Port | Age`), not a refusal, because each branch proved its side of the `||`. The checker hands every later pass a join's base (`types::decay_unions`), so the lowering, the prover and the emitted code are the base's, and a sentence the typed judgment states names the base. A validated record or array does not join, because a store into its part is checked against a declared rule and a union declares none.
- A union is written `A | B` in any type position, with the join's member rules (`types::canonical_union`). Before the checker runs, `ctor::name_unions` makes each written union a validated declaration: its base, the `||` of its members' rules as its predicate, and its members (`TypeDecl::members`), named as the union prints. So every boundary checks a written union through the one validated-type path, and no pass after the checker knows a union exists. A union has no constructor; an alias of one is that declaration under its own name. `jsonSchema` writes a union as the `anyOf` of its members, `fromJson` reads it through a `union` `TypeArg` node that calls each member's predicate, and `schemaOf` refuses one, because a `Schema` describes one declaration.
- An alias without `where` is transparent: `type Id = Int64` names `Int64` and has no constructor. A nominal alias type-checked `Id(x)` that no backend could lower, and a JSON decoder had to answer in a type its body did not produce.
- Refinements stop at predicates and integer-sized arrays. Full dependent types would turn the compiler into a proof assistant.
- `SmallArray<T, N>` is the only type with an integer argument (1 to 64). There are no user const generics, and `Array` has no hidden small-buffer optimization, because that would ripple through the ABI.
- Absence is `Option<T>` and failure is `Result<T, E>` or `Validation<T>`. There is no null and there are no exceptions.
- `Option` and `Result` are ordinary declared sums (`enum { None, Some(T) }`, `enum { Err(E), Ok(T) }`), so one rule serves every sum in every pass.
- An enum is declared `type T = enum { A(Int64), B }` (the user's decision of 2026-10-22). The leading-bar form `type T = | A(Int64) | B` gets the parse error a leading `|` in a type gets, with no hint, as the spellings dropped on 2026-10-01 do; `vyrn fix` rewrites it and keeps every line. `|` in type position spells a union of validated types.
- Accumulating validation is the prelude's `Issue { key, path, message }` with `Validation<T> = enum { Valid(T), Invalid(Array<Issue>) }`. A form needs every error at once, and `key` is a stable i18n id.
- An interpolation whose holes are finite string types is checked by DFA containment. A proof costs nothing at run time, and a failure names a witness string.
- A `lazy T` field holds a `fn() -> T`, with `T` as written, as every `fn` type keeps its parts. A forced read is a call through that type, so it carries its initializer's effects.

### Strings and bytes

- A `String` is immutable UTF-8 bytes. There is no `.length`: `byteLength` is O(1) bytes and `charCount()` is O(n) scalar values, because one name answered two questions.
- `s[i]` is a `UInt8`. String comparison is bytewise and never uses locale collation.
- `'c'` is one ASCII byte of type `UInt8`. There is no `Char` type, and `'ab'` is an error.
- A NUL byte is refused in a `String`, and UTF-8 validity is checked when bytes become a `String`.
- Interpolation is `\{expr}` inside an ordinary string, so `{` and `}` stay literal for LaTeX, SQL and JSON.
- A tagged template `tag"..."` calls `tag(parts, values)`. The parts are compile-time literals and `Value` is the closed enum `enum { IntVal, StrVal, BoolVal }`, so a value can never become structure.
- A user type in a template hole renders through its `impl Show` and is boxed as `StrVal`. `Value` stays closed, because without existentials there is nowhere to put a wider element.

### Functions and protocols

- Protocol conformance is explicit (`impl P for T`) and checked where it is written: a missing method or an extra method is refused.
- No inherent methods. `x.m(a)` is `m(x, a)`, so a helper needs no `impl`.
- Compatibility hints for removed spellings were dropped on 2026-10-01 by the user's decision: a use of `str`, `concat`, `len`, `list`, `push`, `alen`, `array`, `Int` or `Float` gets the sentence any unknown name gets, and those names are free to declare. `at` and `toString` are free too since 2026-10-06: the parser decides a written method-form name once, and the sugar for `a[i]` and for interpolation never reaches a user's declaration.
- Dispatch is static everywhere; there are no vtables. Records are legal impl targets and validated scalars are not.
- Generic impls are keyed on the type constructor: one impl per protocol and constructor.
- A generic call or record literal solves its callee's type parameters renamed apart (`T'n`, fresh per instantiation), so a caller's `T` never meets the callee's. A sentence and the check's record carry the written name.
- Protocols take associated types, not type parameters. No `protocol P<T>` and no `T::Output`: an operator like `?` has nowhere to name the instance.
- A type declares its properties by implementing compiler-known protocols (`Owned`, `MustUse`, `Fallible`, `Copy`, `Iterate`, `Hashable`, `Show`). Built-ins have seeded rows and a declared row wins, so no hand-written list can fall out of date.
- A scalar renders through the language's own lowering; `impl Show` is consulted only for a type the language cannot render. Records get no derived `Show`.
- Any expression may be a method receiver, evaluated exactly once.
- A call names a function or a binding. No call on an arbitrary expression (`r.f()` on a field, `xs[0](x)`); bind it first.
- A bare call `f(x)` resolves to the nearest binding first: a local of `fn` type is called through, a local of another type is refused, and only an unbound name reaches a function. Lexical scope, so a local never silently loses to a function.
- A dot call `x.m(a)` is taken by a local `m` of `fn` type and skips a local `m` of another type, which cannot be its target. `let count = xs.count()` beside `ys.count()` stays legal.
- A function value lowers by defunctionalization: one closed tag per source and a direct call per signature. No function pointer or indirect call exists in any module, because whole-program compilation knows every callee.
- Captures are read-only snapshots taken where the lambda is evaluated. A lambda may not contain another lambda literal, and a function type may not take or return a function.
- Function values have no `==` and never cross the wire.
- A lambda is `x -> e`, `(a, b) -> e` or `() -> e`.

### Control flow and operators

- `if` as an expression needs an `else`, and each branch is one braced expression. No ternary and no block values.
- A block has no value. A match arm may be a block only in statement position; an expression `match` keeps single-expression arms.
- `if let` is a statement; `while let` is `while true { if let ... else break }`.
- A refutable `let Variant(x) = name` traps on a miss. Its scrutinee is a name, and it matches user enum variants only.
- `break` and `continue` are unlabeled. No `loop {}`, no `break value`, no `let ... else`.
- No compound assignment (`+=`). If it comes, it comes for every operator at once.
- Bitwise operators take two operands of one sized integer type. Signed `>>` is arithmetic and unsigned `>>` is logical.
- Bitwise operators bind tighter than comparison and looser than `+`, so `x & mask == 0` means `(x & mask) == 0`.
- A shift by the bit width or more, or by a negative amount, traps, and is a compile error when the amount is constant. C's undefined behaviour and x86's masking are both rejected.
- `%` is truncated remainder on integers only. `a % 0` traps; `INT_MIN % -1` is 0.
- `??` is handle-or-default on `Option` and `Result`, desugared to `match`. It binds tighter than comparison and is right-associative.
- `?` propagates the whole failure unchanged; it never converts error types. On a user type it goes through `Fallible`'s `isSuccess` and `success`, never through variant order.
- `a[i]` traps out of bounds rather than returning a `Result`. An operator in a hot path does not return its failure.
- `panic(msg)` has type `Never`, prints `error: msg (file:line)` for the line where it is written, and exits 1. Only user code panics; std returns `Result`.
- No `==` on a `Map`.
- `Map` iteration, printing and JSON follow insertion order, so hash order is never observable.
- A `Map` key is `Hashable` and owns no heap: sized integers, `Bool`, `String`, records of those, and fieldless enums. Floats (NaN breaks reflexivity), heap fields and payload enums are refused by name.

### Modules, state and effects

- The loader flattens modules into one program; the checker and emitter never see a module. Import cycles are refused, and impl coherence is global.
- `import * as ns` binds a compile-time name that is not a value, one level deep. No `import * from` wildcard and no re-exports.
- A private name that collides across modules is renamed by the linker. A collision with a name the module itself imports is an error.
- An export a library shares with one companion module is `export to "<path>"`, a qualified export as in Java's `exports .. to`, so it stays off the public page and out of completion. The loader's visibility pass is its one check; a path names a file, so a generated module is never a permitted importer.
- A sentence quotes a declaration as its module wrote it, never by the linker's name, through the loader's one rename table (`ast::Spellings`). Where one sentence shows two declarations of one spelling, each declared outside the sentence's module adds the path its module imports it by: `Cfg from "./lib/cfg"`. A runtime module's reserved spelling reads the same way: `json$Json` is `Json`. Hover, completion details and type hints follow the same rule.
- Importing `Result` or `Option` from `std/result` or `std/option` is legal and changes nothing; ambient use stays legal.
- A name whose body lives in std is an import, not a global, and a missing import names its module. `print`, `bytes`, `panic` and `parse` stay global.
- Module state is a top-level `let` in any module, one instance per process and private to its module. `export let` is refused: export accessor functions.
- Module state initializes before `main` in import order, lives for the whole run, and cannot be consumed or dropped.
- Once-only work at run time is module state. No `once` keyword, because grammar is the most expensive thing to add.
- `extern fn` is the only way into the host, under the wasm import namespace `vyrn`. On a target with no host, a call traps with `extern \`name\` is not available on this target`; it is never stubbed.
- Every wasm export and `vyrn.*` import declares its signature in the `vyrn:exports` custom section. A host reads types from it and never infers them from the ABI.
- An artifact is an entry plus a target (`native`, `wasi`, `browser`). The target is a capability set; `wasi` and `browser` are the same bytes.
- The capability floor: the capabilities an artifact's linked closure uses must be a subset of its target's set. The sets are compiler constants no manifest can edit.
- The floor tracks four capabilities: `fs`, `stdin`, `args` and `extern`. Output, clock, entropy and threads are universal, because a row that refuses nothing says nothing.
- A capability is carried by what the source contains, not by which branch runs. For `extern` it is a call to an import, not the declaration.
- The time and random host imports are provided on every target and are not the `extern` capability.
- A module's audience (server, client, universal) comes from the nearest directory segment `vyrn.json` names. An import that widens the audience is a checker error.
- Audience is a fence against accidental imports, not a secrecy guarantee. The compiler cannot know what a secret is; the capability floor sits under the fence.
- A module contract (`contract`, a contextual word) is an ordinary library declaration, checked by `std/contract` over `moduleInterface`. The compiler hardcodes no convention.
- Contracts are closed by default: an export the contract does not name is an error with a did-you-mean. An open rule serves only where names carry no meaning.
- The contract matching rules have one home, `std/contract`. `vyrn why --contract` runs it compiled; Rust states no matching rule. It reads a `.vyrn` module linked, as the generator does. The did-you-mean distance keeps one Rust twin (`contracts::edit_distance`), pinned to `std/strings:editDistance` by test, because the checker asks it and runs no compiled Vyrn.
- The app root has one rule, `manifest::app_root`: the directory of the nearest `vyrn.json`, found by the same unbounded walk as `manifest::find`, else the start directory. The editor and `vyrn why --contract` both use it.
- Mutation on a procedure is declared with `mut fn` and is transport-free. An unmarked procedure is a query; nothing is guessed from a name.

### Test, bench, logging

- `assert` and `assertEq` are legal only in a `test` body; tests and benches are checked and then stripped from `run` and `build`.
- `blackBox` is legal only in a `bench` or `test` body.
- Logging is `logger(name)` with five levels, and the level and sink are set in one static `logging { level, sink }` block. Logs go to stderr.

## Memory

- There is no tracing garbage collector. Memory is released at points the rules define.
- Ownership is defined by rules, not inferred. A program compiles with known reclamation or fails with a fix named in the error; a best-effort inference leaked whenever it was unsure.
- A type that owns heap, directly or transitively, moves on assignment, argument passing and return. Scalars and records of scalars copy.
- A parameter is `read` (the default), `modify` or `consume`. The capability is the API contract, and bodies need no annotation.
- `read` and `modify` borrows are second-class. They cannot be stored, captured by an escaping closure, returned or handed to `consume`, so no lifetime annotation exists.
- A `fn` type carries no capabilities: a function value reads every argument, a function with a `consume` or `modify` parameter is no function value, and a lambda takes each parameter by `read`.
- A `consume` argument is exclusive in its call, as a `modify` argument is: no other argument names it or a place overlapping it. The kernel states it; a rebuilding builtin's receiver is put back, not consumed.
- A function returns an owned value. No borrowed return; projections cover in-place access.
- A place owns its contents. A store releases what the place held, and releasing an aggregate releases its places.
- Copying is explicit, spelled `x.copy()`. A hidden copy is an unbounded cost that nothing at the call site shows.
- A validated record literal that is a part of its parent (an array literal's element, a field, a variant's payload) is built at its offset in the parent's storage, and its `where` check reads it there (`Fn_::core_ruled`). A slot and a copy would be a hidden copy. A failed check traps with the bound literal's words and frees nothing, as every trap does, so the parent's earlier parts stay unreleased.
- No reference counting, deep copy on assignment, region inference or linear-everything. Each adds run-time cost, hidden behaviour or annotations on the common path.
- No drop flags. An ambiguous join (moved on one path only) gets a release on the other edge or is refused.
- A join arm that yields a name bound outside the construct moves it; a later use is refused with the `.copy()` fix. Treating the yield as an alias leaked the name on the edges that did not yield it.
- A projection (a field, element or pattern binder of a place) borrows its root. It may be read, not stored or returned; the fix is `.copy()` or a take.
- A read through a `lazy` field names no place: each read forces the field, and a part of the forced value is the reader's, as a part of a call's result is.
- A refusal quotes what the reader wrote, never a compiler temporary (`@t1`): `vyrn_lower::rules::refusal` panics in a debug build on a sentence that does.
- A lend is refused, never tracked through stores. Tracking it would need an alias analysis.
- `consume <place>` moves a value out of a place; only the taken path dies. No `take` keyword and no `.take()`: an element leaves with `swapRemove`.
- A statement's value is released where the statement ends. A part read as a statement (`p.f`, `xs[i].f`) takes nothing: only `consume` moves a value out of a place.
- A heap part of an element of a call's result (`mk()[0]`, `mk()[0].s`) is copied, and the result is released whole: a release cannot skip a hole in one element. An element of a type with `impl Copy` is copied by the impl where it is taken; a field under one and a scrutinee stay borrows.
- Iterating a place binds a `read` borrow. `for x in consume xs` takes the container; a loop over a temporary owns its elements.
- A `let` of a place read from a `read` parameter is a borrow. Writing through the root while it lives is refused, and the fix names `.copy()`.
- When unsure, the compiler leaks rather than double-frees. A leak is a counted row; a double free is a crash.
- The system is affine: an undisposed value is released at scope exit. `impl MustUse` is an opt-in obligation, separate from `consume`, and it passes through containers.
- `Stream<T>` is linear: consume it with `for`, return it, or `close()` it. It cannot be stored in a field, element, type argument or module state.
- A must-use refusal quotes the binding's resolved type (`Stream<Int64>`), not the producer's spelling. A generic body is judged per instance and refused once per binding.
- A generic parameter does not launder an obligation: a linear value passed through `T` is owed like any other linear binding.
- A self-referring type declares `impl Owned`. The declaration gives the structural release walk its bottom.
- Aliasing is a `Handle<T>` into a container you own (`std/slots`): slot, generation and owner in three plain words. `s[h]` traps on a dead handle and `get` returns `Option`. The library measured 2x faster than the compiler slab it replaced.
- The run-time memory surface is `malloc`, `realloc`, `free` and `memcpy`, plus the explicit `region` arena. No engine checks a generation counter.
- `region { ... }` is explicit, a real bump arena, routed lexically. Inference is refused: 0 of 3,758 corpus bindings qualify, and the arena costs up to 1,023x the memory. Reopen with 20 qualifying bindings and a benchmark the arena wins.
- A heap value inside a `region` cannot go to a `consume` parameter, and in-place append is refused inside a region.
- There is no view type. A stored view is a source plus a locator (a byte range, a path, a handle), checked at use. A locator adds no heap edge, so it carries no proof obligation.
- A projection is spelled `-> read T` or `-> modify T` on an impl member and is inlined at the access site. Projections are never inferred: an inference could turn a 1 ns alias into a 490 us copy with no diff at the call site.
- An optional projection `-> read Option<T>` is read only by `if let` or `while let`. A protocol may declare a projection, but dispatch through a `<T: P>` bound is refused.
- No call-shaped assignment (`x.f(i) = v`). Write `setF(modify self, ...)`.
- A `String` is one word pointing at NUL-terminated UTF-8, with length and capacity behind the pointer; capacity 0 marks a static literal. Three words would box every enum payload.
- `m.keys()` copies its keys; `Array<T>` owns its elements.
- A map store takes its key.
- No engine counts calls (decided 2026-10-08 by the user, reversing a limit of 1,000 counted in every prologue): a recursion runs until the engine's stack or the shadow stack runs out, and the host hands the overflow to the module's `__vyrn_overflow`, which traps `call stack exhausted`. The depth differs per engine; the counter was the largest single check in the static census, on 3,741 function bodies. A frame may claim 8,192 bytes.
- The native host on Windows keeps 64 KiB of the main thread's stack for the overflow trap (`SetThreadStackGuarantee`). Windows writes the exception frame on the overflowed stack, and the CPU's XSAVE state sizes it; the default left about 4 KiB after wasm-rt's handler.
- An array literal holds at most 512 elements, refused by the checker so `check` predicts `build`.
- A `region` nests at most 64 deep.
- Allocation failure prints `error: out of memory` and exits 1 on every engine. The bound may differ by engine.
- Releasing a deep tree recurses, bounded like any recursive walk. No worklist release.
- No raw-memory view or `unsafe`. `Array` is the primitive and containers over it are ordinary Vyrn; `SmallArray` stays built in because it needs an uninitialized place.
- No transmute, unchecked indexing, inline assembly or atomics.

## Compiler

- One pipeline: the loader, the checker, the lowering to a named core, a kernel that judges the core, and one wasm emitter. Each rule lives in one place instead of once per engine.
- A host enters the pipeline through `vyrn_lower::{load, load_warned, check_and_synthesize}`. The frontend's `check_and_synthesize` types and synthesizes and judges nothing; a host that calls it alone skips every ownership and floor refusal.
- The editor runs the pipeline `vyrn check` runs, passed in as `vyrn_lower::JUDGE`. What only the editor needs (recovery, the index, the judgment memo) wraps the pipeline and never replaces a step of it.
- The judgment memo serves a body's verdict only where every input the verdict read is unchanged: its module's hash, the fingerprint of the declarations its module can read, and the effect judgment's answer for its frames. A cache key that leaves out an input the judgment reads is a defect, not a trade.
- The core binds every intermediate value and makes every memory access a place. A field read is one load, never a record copy; the copy made wasm 13x slower than native.
- The emitter reads a heapless layout the core minted out of a place (an argument, a scrutinee, a `for` head) at the place's address, unless a row of the name's extent writes, takes or drops a root of the place; then it copies. The kernel judges a heapless name as a value and refuses no read after a drop, so the emitter checks those rows itself: `show(mk()[1])` read the array `mk()` returned after its release.
- The kernel re-checks every body the link keeps on every compile with three judgments: ownership, effects and types.
- An imported `std/` module that is not an injected runtime module links only the functions some root reaches by name (`loader::drop_unreached`); its other functions leave at the link. Std's gates check every std body as the root of its own load (`tests/std_suite.rs`, the corpus), so a dropped body changes no verdict. Every body of a user's module, reached or not, stays checked. A load the floor still has to judge, and a program that calls `derive`, drop nothing. Such a module's function bodies are parsed only where a spelling outside them can reach them (`loader::parse_reached`), so a body that does not parse refuses only the program that reaches it; `tests/std_suite.rs` parses every one. A load that declares artifacts parses every body, because the floor reads each one's carriers.
- The ownership judgment is one forward solver over the structured core, a join at each merge and a widen to a fixpoint at each loop, and every refusal is a rule row judged at a use, a scope end, a join or a back edge. No rule gets its own walk.
- A flow-free ownership or typed rule (shape E) filters every row, including rows after an ended path: a dead row is still a program the language refuses. The flow solver judges only reachable rows. Both read their sentences from one table, `vyrn_lower::rules`.
- A whole-program analysis over the call graph runs on `fixpoint::solve` in `vyrn-lower`: components bottom-up, a join the analysis supplies, widening by round number. No analysis writes its own fixpoint loop.
- Releases are placed once, from the core, by one liveness pass. No emitter places a release.
- What one analysis decided about a program (the kernel's placement, the checker's record) lives on that program's `own::Ownership`, and a pass reads the one it is handed. A thread-local keyed by a program's address answered for another program.
- Program state lives in one value, the World, owned above the front end by `vyrn-lower`. The front end declares no slot for lowering to fill, and no thread-local or global holds a program's state.
- The load returns the World its check judged (`vyrn_lower::load_warned`), and the host passes it to every pass over that program. A host that changes the program analyses it again (`vyrn_lower::analyze`); no memo hands a World or a record to the next pass.
- A table is keyed by a resolved id (function, type, declaration, name), never by a spelling; two bindings that share a name merged their facts. A node id is a function id and a local index, so an edit to one function renumbers nothing else.
- An id is a storage index, never an order. Diagnostics and emitted functions follow source order, so an incremental check and a fresh one print the same bytes.
- A type's impls are found through one index by type key, `Program::impls` (`types::Impls`). No pass scans the impl list for a key, and its first impl for a protocol is the one the parser flattens.
- Each relation has one writer, which sets both directions and deletes in a batch. No hooks and no second storage shape for one relation.
- The call relation is between source functions, as an edit is: every instance of a generic and every lambda frame call under their function's row. A call through a value is no edge; the effect judgment keeps its own per-instance graph with the values' closed sets.
- A recheck pulls: each result records what it read (a signature, a summary, a name lookup in a scope, misses included), and a cache that records no reads is off in incremental mode.
- Function bodies type in parallel in one wave, because a body reads other functions only through signatures built from declarations. A worker emits no diagnostic; the merge takes each body's diagnostics and record in source order. Output is byte-identical on one thread, many threads and a shuffled order.
- The lowering's worklist runs in waves on every thread, and the merge follows each body's calls in queue order. The lowering makes no expansion tree, so typing expands every site a walk reads; an optional projection expands only as an `if let` scrutinee.
- The projection expansions belong to one compile: `LoadOptions` carries an `Arc<project::Expansions>`, the loader stamps it on the program it links, a generator's load gets a table of its own because its node ids repeat the importer's, and every pass reads `program.expansions`. Its tables sit behind a lock and its trees are leaked. An expansion's ids and temporary names derive from its site's unit, so no worker numbers one in an order the thread count decides.
- What a host keeps between analyses (the recheck cache, the judgment memo, the kept walks, the watched disk, the foreign-entry warnings) lives in one `session::Session` the host owns. It travels in `LoadOptions::session`, stamped on every program the load links, a generator's included, and is read as `program.session`. `vyrn check` passes none. Each cache sits behind its own lock and answers by its key alone, so analyses on two threads may share one session; the language server still analyses on one thread.
- The linked program numbers its source bodies (`Program::source_id`): functions, `impl` projections, tests, benches, module-state initializers and type-declaration checks, each in its list's order. The lowering takes this numbering, and `Fns::number` numbers the lowering-only frames (instances, lambda frames) after it. The numbering is positional, not stored, so it holds after synthesis appends functions; the checker records a read against a `SourceBody` for the same reason.
- A declaration id is its kind and its position in the linked program's list of that kind; a function's is its `FnId`. A name lookup records `Key::Decl` or `Key::Miss(scope, name)`, and a miss names no table, so a declaration of that name in any table reaches its readers. Only a host that rechecks per function records reads (a program with a `session::Session`, the editor's); `vyrn check` records none. The check reads the program's session once, on the calling thread, into the context every typing worker shares, and the merge takes each body's rows in source order.
- The editor types a body again only when its text or the answer to one of its reads changed (`checker::recheck`), and replays every other body's result; the diagnostics equal a fresh check's (`tests/recheck.rs`). What no read records (the other modules' texts, the root's protocols, contracts and `impl` heads, the host, the surface shadows) is one fingerprint every entry is keyed under. The judgment memo keys no root body, so the placer builds and judges every root body on each keystroke; serving one needs the kernel's own reads recorded: the types it walks and each callee's effect row.
- The editor's lowering reuses the calls a body's walk found, keyed by the serial of the recheck entry that holds the body's record and by the type arguments (`vyrn_lower::lower_reusing`). A reused instance has no facts, and the placer walks it again only to build it. A host that runs an emitter lowers every body.
- The World has no query engine, runtime scheduler, archetype storage or on-disk snapshot. Each pass is a function over the tables it borrows.
- A rule stays in the checker when no other pass refuses the program on the same line. A moved rule keeps its surviving home's sentence.
- The generation fence stays in the checker, because it is the only judgment that runs before a generator executes.
- A surface form that another form can state is a parser desugar, so each walker states one form. `if let` and `while let` are a statement `match` with a `Pattern::Other` arm, and take their scrutinee at its last use as `match` does.
- The interpreter is deleted and there is no `--engine` flag. It was a third value model, and a flag with one legal value is a rule stated twice.
- The oracle is recorded output (`examples/expected/`) and the per-example wasm SHA-256 manifest checked on every CI platform.
- Wasm is emitted directly with `wasm-encoder`. No LLVM, clang or sysroot is needed to build or test the compiler.
- A replaced path is deleted, not kept behind a flag. Gated multiplicity stays true and ungated multiplicity rots.
- The compiler optimizes where a measured gap licenses it. Each optimization names the benchmark and the engine it serves, with its number before and after; one that no number licenses is deleted. No engine is assumed to repair the emitted code: wasmtime does not inline unless asked, and clang cannot see through every shape wasm2c writes.
- `vyrn run` and `vyrn test` leave wasmtime's `compiler_inlining` off. `Inlining::Yes` cut spectral-norm run time from 2957 to 1013 ms, k-nucleotide from 285 to 153 ms and nbody from 1353 to 954 ms, but binary-trees ran 590 to 744 ms, every process paid about 7 ms more to translate (floor 45 to 52 ms), and the 27 `site/app` test runs rose about 10% (`site/export.vyrn` fell 5%; the 28 runs together rose 3.3%, best of 6, interleaved). The benchmark harness runs wasmtime at its defaults too, so the wasm line shows what `vyrn run` does.
- No shared emitter trait or instruction-builder abstraction.
- `wasm-opt` is an optional post-pass over the emitted module, pinned as `binaryen` and run only under `--wasm-opt`. The emitter's output and the wasm manifest do not depend on it.
- The sweep never moves a datum. A data address is an untyped constant, so relocating by value could rewrite a user's integer. A dead datum costs no module byte, and the static area ends at the last live datum or reservation.
- Native code is the same wasm through `wasm2c` and clang `-O2`. No Cranelift route for `build`: against an LLVM baseline it measured 2 to 3x, and `wasm2c` 1.5 to 1.9x.
- The native route passes no alignment flag. On `nbodycols`, moving the hot loop within a 64-byte line changed native time by under 0.6%. Clang's register allocation of the inlined `advance` changed it by 1.0% when `inplace-copies` changed only its caller, so an emitter change is not judged on a native drift near 1%.
- `run`, `test`, `bench --check`, `serve` and `dev` run the module in embedded wasmtime.
- A trapped call into a resident instance (`serve`, `dev`, `test`) keeps the instance. The host restores the stack pointer and region nesting it read before the call; module state and heap blocks stay as the call left them. Re-instantiating would drop the state every earlier request built.
- Control flow stays structured in every intermediate form, because wasm accepts only structured control flow.
- Monomorphization happens once, above the emitter, and an instance is identified by its type arguments, never a mangled string. A mangle collision once miscompiled silently.
- Monomorphization has two bounds: 64 levels of nesting and 65,536 parts. `vyrn check` runs them, so a passing `check` means `build` terminates.
- Every trap wording lives in one table (`vyrn_frontend::trap`), and a test fails on a re-spelled wording. An engine chooses how to raise a trap, never what it says.
- Every runtime check is its own core row, stated once before the row it guards; one runtime check is one row. The emitter runs no check without a row, and a row no construct runs is an error.
- A change that proves checks is licensed by the check oracle (`VYRN_CHECKS`, `scripts/check-elision.sh`): no proved row fails a run, and the elided, kept and oracle builds print the same.
- The check oracle counts a row's runs in the site table the profile uses, with a function the module holds, not a host import: 2.8 times faster on `nbody`. A row keeps its own site when another has its key, so duplicates stay duplicates in the log.
- A check row is proved only with a certificate that a checker sharing no code with the search accepts, or, for a divisor, a disequality `d != 0` the state holds, which a comparison or a passed divisor check states. The search chains at most three premises for a check's goal and two everywhere else (`facts::Prover::ge0_deep`), and asks a goal whose coefficients share a factor divided by it, its constant floored (`facts::Cert::Scaled`). A premise's rest of one term `k*t + c` takes the premise on `t` `|k|` times: `off + 4 * t` from `off >= 0` and `t >= 0`. A direct call's whole `modify` argument keeps the facts of each slot no row of the callee writes (an array or String field's length, an integer field's value, an array's own length) and the lower bounds of a length the callee only appends to (`elide::frames`, the least fixpoint over the call graph); a call to a row with no body here moves every slot. Until builtin rows state length effects (#12), every other `modify` or `consume` argument forgets its name.
- After a join, a Bool's side drops a fact only where one premise of the joined state states it (`facts::Prover::states`). The search chains at most two premises, so a fact a chain proves is still a premise a longer goal needs. On 2026-10-23 dropping such facts kept a binary search's `xs[m]` when `hi` started at `xs.length`: the loop head held `hi <= xs.length`, the guard's `lo < xs.length` followed from it and `lo < hi`, and `d = hi - lo` then needed three premises to be exact.
- A quotient `q = a / k` of `a >= 0` by a literal `k >= 2` states `k*q <= a`, `a - k*q <= k - 1` and, where `a >= 1` is proved, `q <= a - 1` (`facts::divided`, beside `0 <= q <= a`); a unit test checks them over `k` in 2 to 32 and `a` in 0 to 4,999 and below `2^62`. On 2026-10-23 they proved no corpus row. `xs[(lo + hi) / 2]` under `lo <= hi < xs.length` stays kept: `q < xs.length` follows from `2q <= lo + hi` only as twice the goal, which no certificate scales, and `lo + hi` is exact only with a third premise.
- An `if` on a Bool name neither branch writes keeps, as the name's sides, what each branch proves of the lengths of the names it stores, in the walks that decide checks: `let skip = if prepared { skipTable(..) } else { [] }` proves `skip.length >= 256` under `if prepared`. Over every fact of the branch it cost the site export's build 7.3% more allocations, and in the solve's walks 0.3% more for no row; making relevant the condition of a branch that stores a relevant length cost 0.7% more for no row.
- Where one state of a join defines a term as a constant and the term takes too many values to list, the join keeps the least lower bound and the greatest upper bound the states prove of it (`facts::Prover::least`): `k = 0` joined with `k = -e`, `e >= -100`, keeps `0 <= k <= 100`, so `n - k` stays an exact sum.
- A loop whose counter steps by one up to a length it reads at its head (`while i < xs.length`) keeps the counter at most that length, so at the exit the counter equals it and an array the loop pushes in step is as long as `xs` (`elide::bound_test`, `Walk::in_step`). A counter stepped twice a turn can pass the length and keeps only the lower side. On 2026-10-13 this proved `examples/permute.vyrn` `apply`, `inverse` and `cycles` (50,137 of 283,084 kept runs over the fixtures, the Benchmarks Game suite and the site export) for 5.9% more `elide: summaries` allocations on the site export, 1.09% of its build. The counter is relevant to a check only through the rows that link it: marking every such counter relevant in the walks that decide checks cost 2.4% of `elide: summaries` and proved no more rows.
- A callee summary assumes no entry fact, is keyed by the `FnId` of the body that runs (for a call to a generic, the instance row its solved type arguments spell, the one the emitter runs), and is the greatest fixpoint with no round cap or time budget: a cut-short solve would keep facts no walk proved. A refusal never reads one, so `vyrn check` and the emitters refuse alike.
- A callee summary bounds an integer result or an array result's length. A String result has none: no row of the corpus or the site export read one, and the String builders' walks were most of the solve.
- A Bool result's summary states what its `true` returns prove: an index in range over the parameters and their records' fields, one deep. The caller assumes it where the call is true, and a write to an argument drops it. A field's index binds only an argument of the parameter's type. A returned `a && b` states both operands' facts: a join sums a condition's facts with the state's to drop a name its branch bound.
- A sentinel, a function whose integer result some return makes negative (`return 0 - 1`), states the guards of its own index reads (`i >= 0` and `i < a.length`, over its parameters and their fields) for every return of a value at least zero (`elide::Summary::when`). The caller assumes them on the side of a comparison of the result that alone shows it at least zero: `peek(p) == '('`, or `c < 0` false. So a parser that tests `peek` and then advances its cursor keeps the cursor's record facts.
- A check on a global's array field reads the length of a borrow of the global (`let b = read global g`) until a row may write `g`. The effect judgment's write set per frame (`effects::StateUse`) is the one source of what a direct call writes; any other call but a constructor, and a release, may write every global. The borrow keeps its own facts, because the kernel ends it at a write.
- A callee summary states the integer fields of an `Option` of a record's payload (`elide::payload_fields`), as it states an `Option` of an integer's: at least zero, against each integer parameter and each length. A record result states nothing until a program needs it. On 2026-10-13 it proved the `nextMatch` clause in `std/regex` `replaceAll` and `countMatches` (4,026 runs) for `elide: summaries` 0.04% more allocations on the site export.
- A parameter's `where` clause is checked at every call row and assumed at the body's entry, an exported body's too: the assumption rests on that check, while the rule below is about inferred entry facts, which nothing checks. A clause reads only `read` parameters and has no arithmetic, so it holds for the whole call and each comparison is an exact linear fact. A failed clause traps at the call, never refuses: a call the prover cannot show keeps its check.
- A parameter's clause may state the parameter's own `.length` or `.byteLength` (`skip: Array<UInt32> where value.length >= 256`), as it states an earlier parameter's. The stability argument is the same: only a `read` parameter carries a clause, so the length holds for the whole call. A table a callee shortens through `modify` before the call is caught by the call's check.
- A body's entry facts are assumed only where every entry is a direct call row of a walked body: never for an `export`, `extern`, `gen`, `main`, `impl` method, derived function, `std/runtime` function (the emitter calls one by name), generic function or function with a `fn`-typed parameter, nor for one any row names by its spelling, one with a caller row that has no walked body, or one no row calls. Each caller proves them walked once, without its own entry facts, so no entry fact rests on another.
- Entry facts stay walked once, except for a caller whose own `pre` holds an element template: such a caller is walked under its `pre`, as a greatest fixpoint after the other callers (`elide::summaries`). The fixpoint over every caller is sound by induction on frame creation, but on 2026-10-12 it proved one more row of 397 roots (`examples/fasta.vyrn` `pick`, never run), moved none of 1,041,920 kept check runs and cost `elide: summaries` 35.8% more allocations. A template chain pays: `fannkuch` `foldCount` proves `flip`'s `pre` from its own.
- Element bounds use the record-fact domain: keyed by field names for a record field (`elide::RecordFacts`) and by array name for a local array (`facts::State::elems`). A branded index or a bound in the element type is rejected, because the type would depend on a value whose length changes while indexes exist. A quantified clause on a `read` parameter waits for a program that needs a host-boundary contract.
- A local array's element template is the bound with the element as a hole. It is no fact, because an empty array meets every template; an element read instantiates it. A store or `push` the walk proves meets it, `append` of an array that holds it, `copyFrom` and `clear` keep it; a growth keeps a template with a positive length coefficient and a shrink one with a negative coefficient. An unproved store, a `modify` call, a replacement, and a join or loop turn that loses it drop it. No template names a global. A summary's `pre` and `post` carry the templates of an index array (`elide::index_elements`): a `pre` only for a parameter whose element feeds a kept check's index or a call argument, a `post` only the strict bounds of an array result. A call row meets a `pre` template also from a record fact, where the argument borrows the field (`weightBare(m.xs, m.idx)`); only a fact a check on the record seeds can. On 2026-10-13 that, with the element rows, proved `examples/fannkuch.vyrn` `flip` (71,220 runs), `examples/indexbuffer.vyrn` `weightBare` (50,460) and `examples/permute.vyrn` `cycles` (10,000): kept runs over the fixtures, the Benchmarks Game suite and the site export from 414,764 to 283,084, for `elide: summaries` 3.0% more allocations on the site export. Removing `flip`'s check moved `fannkuch` at order 11 by -1.7% native and -1.9% wasm, best of 11 interleaved runs, inside a noise band of 62% between a run's best and worst, so the gain is in checks, not yet in time. On 2026-10-12 it proved `dist[v]` in `bfs` of `examples/csrcount.vyrn` and `examples/csrpush.vyrn` (16,000 runs) and no other corpus row. Every alias of an array's root (`@borrow = read a!`) must lose the fact at a store into the root.
- A fact that relates the lengths of array fields of two records of two types crosses calls. A body only call rows enter proposes, for each array field of a record parameter a kept check indexes, that it is at least as long as each array field of another parameter; a function that returns a record proposes each array field equal in length to each array field of a parameter it never writes. Both only for a `elide::Pair`: two declared record types such that a body indexes one by a value of the other and a body makes one from the other. A caller takes each such fact a callee's `pre` states of its own parameters as a candidate (`elide::forward`) and is walked under its `pre`. The terms are the existing `Term::Col`, so a store into the field, a shrink and a `modify` call whose frame moves the field forget the fact as they do in one body. On 2026-10-13 this proved `std/regex` `addThread` and `intern` (928 of 232,947 kept runs) for 0.34% more `elide: summaries` allocations on the site export; pairing a record with an array parameter as well cost 10% and proved no more.
- A user function's element row (`elide::Frame`, beside its `frames` moves) states that every element of its result, or of a `modify` argument at exit, lies between the least and the greatest element the argument held at entry. A walk derives it with two ghosts per index array parameter (`elide::index_elements`: integers wider than a byte, whose type bounds them), fresh terms G and H bound once at entry: an element read gets `G - v >= 0` and `v - H >= 0`, arithmetic keeps them only where the prover shows the bound exactly (`a[i] = a[j] + 1` meets no ghost), and a store, push or return of a value that misses either makes the row unknown; a result built from another array has no row. The ghosts are universal, so a value at exit is at most the entry maximum, and an argument empty at entry yields no element through the row, because every value the row admits was read from an entry element. A caller carries each template of the argument whose other terms the call leaves unchanged: one bound by the argument's own length holds where `frames` keeps the length or only grows it, and a result keeps the argument's length as a term, because it may be shorter. Two parameters never name one array: a `modify` argument is exclusive in its call (`tests/refusals.rs`, "a modify borrow read again in the same call"). Rows join beside `frames` as a greatest fixpoint from every row holding: a call that returns makes its calls at a lesser depth, so by induction on that depth their rows hold where the walk reads them, and a call that does not return claims nothing.
- The length of an element array an index name picks (`r.f[i].length`, `xs[i].length`) is one term, `facts::Term::Inner`, and bounds a read of the same element by the same index name. Any row that may write an element forgets every such term: a store into a field, an element or a key, a take, and every call but a builtin that writes no argument. A store into a name or a write of the index forgets the terms that read it. Every write forgets them all, not only those of its own array, because the core's hoisted borrows (`let @borrow = read g.rows`) read the elements a store through `g` writes.
- The prover reads a record's `where` rule: `a.length == b.length` makes one length term of both fields. The rule holds wherever the record is read, because every boundary checks it and every in-place store into a field ends in a check before the next read. From a group's first store to its check, each field's length is a term of its own.
- A record fact (`elide::RecordFacts`: two array fields of equal length, an integer field at least zero, or at least one where a check divides by it, an array or String field at least as long as an integer field's value or longer than it, every element of an integer array field at least zero and below a field's length by one or by a column's reach) is keyed by its field names, because record types are compatible by shape: it binds every record value with those fields, each of the fact's kind. No fact binds a type the host or a builtin makes (an `extern` or builtin signature's types, the prelude's), nor names a field a row writes through a global, an element or a nested field. A module's `export` stays inside the program; only the host boundary makes values no walked body built.
- A record fact's walk assumes, at the entry of a body that builds a record from a parameter's array whole (`Perm { xs: p }`), each fact on that field alone over the parameter (`elide::parameter_facts`), and the body's `pre` must keep every fact the walk assumed, or the solve starts again without the ones it lost. Sound by induction on the steps of a run: the record is built after the body's entry, whose call row proved the `pre` under the record facts of the steps before. On 2026-10-13 it proved `examples/fannkuchperm.vyrn` `flip` 15 (35,610 runs), and the solve started again neither there nor on the site export.
- A lazy DFA names a state by its row's offset in the table, and the table holds 256 entries past every row (`std/regex` `Scan`), so a byte's step `next[s + class]` is a linear goal. The prover has no rule for a product of two values: on 2026-10-11 `s * classCount + k` was the one row of the corpus that needed one.
- An element's bound is inferred, never written, and `Array<Int64 where ...>` does not parse: on 2026-10-11 a validated element type and an inline bound would have paid 1 static row and 0 executed checks of 5.1M kept, against 660,151 for the inferred bound. The inline bound waits for a program that needs it. An element of a validated integer type is a premise, as every name of the type is (below).
- A name of a validated integer type carries as premises its rule's comparisons of `value` with a literal (`check::scalar_rule`, `elide::Walk::premises`): a parameter, a `let`, a field or element read, a call result and a `Some` binder. An operand with arithmetic, which wraps, with `=~` or a call, and a `||` state nothing, so a union of validated types states nothing. The premise rests on every boundary checking the rule (language.md, Validated types). A construction from a name is a check row (`check::Guard::Scalar`) the prover may drop; `vyrn why --cost` lists it where it stays. `pullAt` and `unboxStream` take their element type from the context and check nothing, so a program that unboxes a stream at another type breaks this premise, a record rule's and memory safety alike. On 2026-10-23 it proved 5 rows of the p04 probe and removed 3 `where$c` calls from the examples' wasm.
- In-place stores into the fields of one `where` record group: the maximal run of consecutive statements in one block that each store into a field is checked once, after its last statement, and nothing reads the record whole in between. A `modify` parameter's group calls no declared function or function value and has no exit. A group is found in the core's rows (`core::Builder::stmt_list` writes the check, `typed::groups` judges the rows), and module state keeps the refusal, because every call may read it.
- A group whose rule check the prover proves false (one field of an equal pair provably longer, on a live path) is refused at its first store, since the check fails on every run that reaches it. Only `vyrn check` asks, only for a body with a group, over its own stated copy of the body; the proof is the elision walk's, with `-g - 1 >= 0` for a goal `g`.
- Every limit is one constant, derived where it is used, and a test checks the derivations.
- Error text is canonical Vyrn wording, never the operating system's.
- The parser refuses nesting deeper than 1,024 with a diagnostic, because remote modules and the LSP parse untrusted input.
- Diagnostics speak intent: what you asked for, what blocks it, how to fix it. They say read, modify and consume, never "borrow" or "lifetime".
- A refusal of the lexer, parser, loader, checker, kernel, typed judgment or core builder is a row in `vyrn-frontend/src/rules.rs`: a `Rule` names its holes, its sentence and its fixes, and the diagnostic carries the rule with its hole text. Sites that print the same sentence name the same rule. A way out a site picks by its own state is a row too, rendered under another (`Diagnostic::more`). Text written outside these passes (generator output, manifest and schema errors) stays a string in `Diagnostic::error`.
- The runtime (allocator, strings, maps, arrays, I/O, traps, regions) is Vyrn in `std/runtime`. The raw memory and WASI primitives are declarations in `std/mem`, importable only by `std/runtime`.
- The WASI calls a module imports are one table, `vyrn_codegen::WASI_IMPORTS`. The emitter declares from it, and a test holds each host (`vyrn-genwasm/src/wasi.rs`, `wasi_host.c`) to exactly its rows.
- The embedded WASI host is one file, `vyrn-genwasm/src/wasi.rs`, behind a `Policy`. A program run gets the process (environment, working directory as fd 3, stdin, clocks, random); a generator gets none of it, and a test fails if a call that reads the process reaches its link set.
- A builtin exists only for what Vyrn source cannot express, such as a syscall. Everything expressible is std Vyrn.
- Every fact about a builtin (contract, method spelling, core `Spec`, effect, route, shape map, editor text) is one `prelude::Builtin` row. The shape map states which receiver position each position after the call reads, so the length a pass carries across the call and the class of position map the provenance analysis composes cannot disagree. A pass reads the row, never its own list of names. The checker counts a builtin call's operands from the row's `arity`, and types a row marked `typed` from the row alone.
- A number method that is one wasm instruction at each width (`clz`, `ctz`, `popcount`, `sqrt`) is one row whose `Spec::Unary` lists the types it admits, and the operand's type picks the instruction. `Int8` to `UInt16` are left out: they live in an `i32`, so the instruction would count bits the type does not have.
- Hot per-element paths stay inline in the emitter (indexing, the map value paths), because one wasmtime call level costs 14 to 270% there.
- A `for` over any indexed container is one index walk in the core. A user container supplies its `size` call and its `nth` element read; it gets no loop of its own.
- A `read` or `modify` aggregate parameter is the caller's storage, used in place, unless the callee may store into module state that can hold it (`read`) or read or store any module state (`modify`), as the effect judgment answers per frame; the checker's exclusive-`modify` rule covers the parameters. The rule trusts the judgment to attribute every call, as the kernel's state-write borrow rule does; the `effects` gate holds unattributed calls at 0 over the corpus.
- A `consume` aggregate parameter is the caller's storage, used in place, except in an `export` or `gen` function with an aggregate result, whose out-pointer the host or driver chooses. During the call only the callee touches that storage: module state is never taken, no other argument overlaps it, and every call this module emits passes a destination `Fn_::dest_apart` proves apart from its `consume` arguments, or a fresh slot. After it, the caller never reads a consumed argument. The callee may write the storage (`let mut a = p` takes it over).
- A `consume` record parameter that every `return` yields, never stored into whole (`vyrn_lower::core::returned_param`), is the result: the function works in the caller's storage and writes no separate result. `x = f(x, ..)` passes `x`'s storage, and so does a call whose argument's extent ends at it and holds a frame slot, whose result takes that slot; any other call moves the argument into its destination first. No shared result slot instead: a write to it could clobber a field the body still reads. An `export extern fn` keeps its out-pointer, and a call through a stored `fn` value keeps its dispatcher's, which moves the argument in.
- A flat aggregate (`Cx::flat`: one or two scalar parts, no heap, no declared release, no `where` rule) has two homes, split per name: wasm locals when `Fn_::core_flats` admits every row that names it, its frame slot otherwise. A row kind joins the screen when it has a form over the parts; the slot home goes when every kind has one. A row that needs the value's address keeps the name in its slot rather than spilling it, so no admitted row writes memory the name lives in.
- A flat aggregate result crosses as wasm results, one per part (`Ret::Words`), from every function but an `export extern` or `gen` one, whose caller outside the module passes an out-pointer. Every host the module runs on accepts multi-value (wasmtime, wasm2c with clang, `web/wasi-min.js`). The result and the locals home go together: the result ABI alone moves the stores from the callee to the caller, and only a caller that keeps the parts in locals saves them.
- On Windows x64 the native route declares every multi-value function `sysv_abi` (`toolchain::sysv_multi_returns`), so two words return in RAX:RDX as on Linux. The Windows convention returns them through a hidden pointer that clang fills with one 16-byte load, which the store buffer cannot forward from two 8-byte stores: membench's "stream open and close" ran 1.25x slower. The rewrite holds while the module takes no function's address, which `Module::sweep` enforces.
- Runtime modules are injected on mention under unlexable `$` names, so user names neither collide with them nor capture them.
- An impl method flattens to `Protocol$Key$method` (`types::impl_method_name`), so no user name spells one. A key may hold `$` (`Copy$json$Json$copy`); a protocol or method name never does. The linked name flattens the linked protocol and key, so it follows their renames, and two impls of one protocol for one type are the checker's refusal alone.
- A generator runs as compiled wasm in embedded wasmtime. Each capability that needs compiler machinery (read, list, `moduleInterface`, `lex`, `contractOf`, code quotes) is a host import, so there is no second implementation.
- Generator budgets use wasmtime fuel, never wall clock, so a limit is deterministic.
- A generator is comptime-pure: no `extern`, module state, file writes, stdin, `args` or logging. It reads files only under its constant path arguments, and every file it reads joins its cache key.
- The generator cache is keyed by everything a generation observed and authenticated with a per-user secret. It is never restored across CI runs: a restored cache is untrusted compiler input.
- Type reflection is a flat array of `TypeNode`s whose edges are indices, so no recursive Vyrn type and no new decoder shape is needed. A declared name is a leaf; kinds are strings, like `Schema.base`.
- A derived-code generator receives one `TypeArg`: a graph over the checked types its call sites need, a node per `struct_key`, each node's kind `codec::wire`'s verdict. The codec rules stay in Rust; the generator only writes text.
- A `derive` generator runs once per program over every type its sites need, cached in-process by its program and argument. A run per type would write a shared subtype twice. Its compiled module persists across processes under a hash of the trimmed program's canonical text, which sorts the AST's hash containers. What it writes is checked against the program: only its bodies are typed, because a body's verdict depends on the declarations and not on other bodies.
- Derived code lives in std as a `derive` generator, not in Rust. `toJson(x)` is `derive(jsonEncoders, x)` with `std/json`'s generator, and `fromJson<T>(s)` calls what `std/jsondec`'s `jsonDecoders` writes for `T`; a generator's own program may reach `derive`, but not its own generator.
- A `derive` generator may write type declarations as well as functions; both are renamed under `derive$g$`, which no source can spell. A `where` type is its own `TypeArg` node over its base, carrying the sentence its failure reports; written code calls the declaration's predicate `where$p<Name>` through the `VyrnWp_` placeholder, so the predicate is stated once, in `ctor`.
- The playground runs a generator in the page: `vyrn-genwasm` without `host` builds the module and the `TypeArg` atoms, and `play-wasm.js` runs it. The page serves no read, no module reflection and no code quote, so only a `derive` generator runs there.
- An editor call runs a companion unchecked when the engine holds a module compiled for the companion's fingerprint, because the fingerprint and the compiler's identity name every input of the check; an input the check reads joins the fingerprint before a check is skipped on it.
- The playground's editor calls the `vyrn-frontend` functions `vyrn-lsp` calls (`member_context`, `scope_completions`, `member_completions`, `resolve`), so the page and an editor cannot answer one cursor differently. The page adds only what it alone holds: the embedded std module names.
- The playground's painter and `site/app/hl.vyrn` give one token one class; `site/test/playpaint.test.mjs` compares them over the landing page's cards.
- A generator emits code through code quotes (`vyrn"..."`). A string spliced into an expression becomes an escaped literal and into an identifier is validated; there is no way to splice a string as code.
- Code quotes and `lex` exist only during generation and are not reserved words.
- A column layout (one array per field of a record) is `std/columns`, an import-target generator over `moduleInterface`, not a language feature. Its container's `where` rule states that every column has the first one's length, so a loop bounded by one column indexes all of them unchecked. `derive` cannot write it, because its call answers `String` and renames the types it writes. A push appends to every column in place, as one group of stores whose rule check the prover drops.
- Generated code maps back to its input through `//@origin path:line:col` lines, which any generator may emit. A diagnostic that cannot be remapped stays at the generated location; it is never dropped.
- A generator reports a diagnostic by writing `//@diag <severity> <anchor> <message>` into its output, so the report survives the cache. Two severities; an unknown word is a warning.
- The compiler knows no lint rule names, codes, registry or suppression syntax.
- A generator symbol map is an exported function inside the generated module, so it cannot go stale against cached code.
- A generator module's editor support lives in its editor companion, `<stem>.editor.vyrn` beside it, which no program links, so a program that uses the generator pays nothing for it.
- A generator or library tells tools its conventions through its companion `<stem>.editor.vyrn`; no compiler or LSP source names a std module, a generator, a stem or a call.
- A companion extends the editor through exported `gen fn`s with fixed name prefixes, searched in the claiming generator module's companion, then the companions of the modules it imports, depth first. A name is program-wide, so each companion appends its own slug, as `symbolMap` does. `vyrnComplete<Slug>(root: String, path: String, line: Int64, col: Int64) -> String` returns completion items as JSON; `root` is the claim's argument, so the function reads beside the input under the sandbox's own rule. `vyrnSource<Slug>(path: String) -> String` returns the input with every character outside Vyrn code replaced by a space and each LF kept, then the declarations the file's form provides; its positions are the input's, so a tool maps none. `vyrnDefinition<Slug>(root: String, path: String, line: Int64, col: Int64) -> String` returns the definition of a name the input's own grammar declares, as an anchor in `//@origin` notation, or an empty string. `vyrnSymbolMaps<Slug>() -> String` names, one per line, the module's generators that bake a `symbolMap` export into what they write. `vyrnChrome<Slug>() -> String` names, one per line, the file stems in a role's directory that are chrome and answer no contract; a `vyrn.json` role that lists `except` overrides it. `vyrnClassCall<Slug>() -> String` names the function of a module the generator writes whose string argument is a class list, and `vyrnStylesheet<Slug>() -> String` the zero-parameter function there that returns its stylesheet. `vyrnDevServer<Slug>() -> String` names, one per line, the generators that mount a server surface, so a root that calls one is a root `vyrn dev` serves.
- A generator import's identity is its resolved path arguments, so two spellings of one path are one module.
- A JSON Schema type import round-trips byte-exact with the schema emitter; an inexpressible keyword is an error, never a silent drop.
- The placer rebuilds a body its placement touched; placement is not an edit of the core (95% of rebuilt bodies only gain `drop` statements, 5 in 938 renumber names, and the name numbers decide the order of wasm locals). The rebuild runs on every thread and merges in job order.

## Standard library and web

- std stays Vyrn. No std function gets a native body, and speed comes from the algorithm (Horspool, SWAR), not from a second implementation.
- One `String` type, with several algorithms behind one function; the cheap path allocates nothing.
- Failure in std is a value: `Result` over small per-operation error enums.
- Floats format through `std/num`'s `f64Str`; text to number is `std/num` over the bit views `floatBits` and `floatFromBits`. No `parseFloat` builtin.
- A std integer is unsigned only when it holds bits that never go negative (a byte, a hash word, a bit set, a code point, a random state), in the smallest width that holds them. Lengths, indices, offsets, positions and quantities stay `Int64`, because unsigned arithmetic wraps silently and the check prover keeps no range for a `UInt64`.
- `std/strings` is ASCII for case and whitespace; `split` on an empty separator returns `[s]`, and `indexOf` returns `Option`.
- `reserve`, `append`, `copyFrom` and `clear` exist on growable `Array` only, and are refused for elements that own heap.
- `m.tally(k, n)` is one probe and never takes the key.
- The runtime never calls a user's hash. It hashes a zeroed canonical pack of the key, so no engine can disagree.
- `std/regex` is a Thompson NFA with no backtracking: the RE2 subset, leftmost-longest, linear time. `=~` stays an anchored compile-time match.
- A `std/regex` search runs the NFA as a lazy DFA over byte-class runs, built per search; past `dfaCap` table entries it falls back to the Thompson simulation, so a search's memory stays bounded and its answers stay the simulation's.
- The JSON codec is canonical: declaration order, no whitespace, `None` fields omitted. `fromJson` returns `Validation`, runs every `where`, parses integers exactly, ignores unknown fields.
- `std/json` is the one strict JSON reader: numbers keep their text, duplicate keys and trailing commas are refused.
- `fromJson` reads its document once through `std/jsonread`'s `JsonReader` and writes each value into its record; it builds no `Json` tree. `parseJson` reads with the same functions, so both refuse a document at the same position with the same sentence. A refused document yields its `json.parse` Issue alone, and a record's Issues follow its declaration order, not the document's key order.
- A payload enum crosses the wire externally tagged (`"Unit"`, `{"Circle":5}`, `{"Rect":[2,3]}`), one wire form per value.
- `Map<Int64, V>` crosses the wire as a JSON object with canonical decimal keys; user-keyed maps are refused by the codec.
- VON is Vyrn's record-literal grammar as a data file, read by the compiler's own lexer. It refuses null, interpolation, anchors, environment references and duplicate keys.
- Time and randomness are host inputs: `now()`, `monotonic()` and `randomSeed()` are the only host calls, and the PRNG is a value threaded explicitly. No global `random()`.
- `std/time` is UTC only: no timezone database, `Duration` or date parsing.
- `std/storage` writes atomically (temp file, then rename). `fsyncFile` is opt-in, because an fsync per save costs real latency.
- `std/args` is the minimal argv reader. `std/cli` makes a record type the command: one declaration yields parse and help, and there is no `--version`.
- A lint rule is a library (`std/hints`, `std/vyx-hints`), fires only when it is certain, and is waived by `vyrn-ignore <code>` in the input. No lint framework or `vyrn lint`.
- Typed RPC is a library of generators over an ordinary module. An `Err` return is a 200; 422 is reserved for request validation.
- Each RPC path is derived as `/_/{module}/{name}`. Overrides are data (`rpc.json`), and colliding paths are errors.
- A procedure is serializable only if the compiler's codec can encode its types. A `Stream` is refused by name and pointed at SSE or WebSocket.
- No single service description projected onto every transport. Each protocol has a hand-written `<stem>.<proto>.vyrn` in that protocol's vocabulary.
- Connect, OpenAPI and GraphQL are generator libraries over `moduleInterface`. No gRPC, which would be a runtime project.
- The GraphQL executor is generated beside the SDL from one reflection walk. A resolver's `Err` stays in `data`.
- A client disconnect is detected when a write fails. No keep-alive or ping; a finished producer answers 204.
- WebSocket support is server push only.
- An ETag is FNV-1a-64 of content type and body with no seed, so it survives a restart. Cache-Control is a bare `max-age`.
- `mount` takes the first match. An overlap is a startup trap.
- Streams are pull-based. No `channel` and no arrival-order `merge`, because nothing can push.
- A failing producer yields `Stream<Result<T, E>>`; there is no second error channel.
- The UI layer (`std/html`, `std/ui`, `std/vyx`, `web/`) needs no compiler change, so anyone can build a competing framework from the same parts.
- `std/html` escapes values and checks tag, attribute and event names.
- Unescaped markup is a type: `Raw` and `v-html` take `Markup`, built by `toMarkup` or by `TrustedMarkup` for markup the program owns. Vyrn cannot seal a constructor (a variant is program-wide, a record is structural), so the hatch is one named variant a grep finds.
- The DOM diff runs in wasm and crosses as a list of patch operations in a fixed order, so a naive applier is correct.
- `.vyx` templates use one Vue-flavoured grammar: `{{ }}`, `v-if`, `v-for` with a required `:key`, `:attr`, `@event`, `<slot/>`. No `v-model`.
- `std/vyx` names no component. Every capitalized tag is a sibling `.vyx` file or an imported provider, so it is not a framework.
- Pages declare data through `export fn data()` returning `Query`, `Lazy`, `ParamQuery` or `ParamLazy`, and head through `export fn head()`. Laziness is in the type name.
- A layout is the nearest `layout.vyx`; a load failure renders the nearest `error.vyx`.
- The first load is full SSR; navigation renders on the client, and falls back to an HTML swap, then a hard navigation. Soft navigation is progressive enhancement, never a correctness layer.
- Page data is served by content negotiation on the page URL (`Accept: application/json`), and no response carries the string "vyrn".
- `std/tw`'s class vocabulary is closed and checked at compile time: no arbitrary values, no `dark:`.
- Icons resolve at compile time from hash-locked collections, never at run time.

## Tooling

- The workspace builds and tests with no LLVM, clang or sysroot. `vyrn-lsp`, `vyrn-genwasm` and `vyrn-play` sit outside it.
- `vyrn fmt` has one style and no options, never joins or splits lines, and refuses any output whose tokens differ from the input's.
- `vyrn fmt` and `vyrn fix` write the canonical target path (symlinks resolved) through a staged file in the same directory that copies the target's permissions, and refuse with a sentence naming the file if its bytes changed between the read and the write (`manifest::rewrite_whole`).
- `vyrn fix` applies only `.copy()`. `consume` and `for x in consume xs` change a contract, so they stay the author's decision.
- `vyrn why --cost` reads the decided core and replaces `vyrn why --memory`. The LSP hover keeps the binding rows of the ownership table, with one wording.
- The provenance analysis (`provenance::of`) ignores conditions, so a class holds for every answer a predicate gives. It reads no callee summary, and a builtin moves positions only as its `ShapeMap` row states. `vyrn why --provenance` is its one reader until the fact judgment reads it.
- A kept check's reason is a field of `Check` (`Why`), written with the verdict, not a side table: one home for a check's facts. It speaks source terms: the goal as the source would test it (`` `xs` non-empty ``, `` `i < xs.length` ``), and the change that would drop the check where one exists, such as a parameter's `where` clause.
- The editor's cost hints show every row `why --cost` prints, with no loop or profile filter. Loop depth counts only the function's own loops, so a filter by depth hides a function its caller runs in a loop, and a profile counts no checks. A label is a few plain words, and the tooltip holds the reason. A function lens shows only what the last profile counted: a lens of counts repeated the line hints.
- A function of another file counts its allocations at the line that calls it. The cost report is a report: it raises no warning.
- The last `vyrn run --profile` is saved per root, stamped with a hash of the root's source and the content hashes of its imports. `vyrn why --cost` shows it only while the stamp matches, so it never shows a count against a line that moved.
- `vyrn run --profile` counts blocks per source line with the free audit plus a `SITE` global. The instrument is off in every other build, so the wasm manifest does not move. A block made inside `std` counts at the last site that ran; a call path per site would need a shadow stack.
- `vyrn run --profile` counts each function's calls and operations by rewriting the finished bodies (`wasm::count`), at the prices of wasmtime's fuel meter. The instrument's own instructions, and the calls they make, are marked on the `Frame` and run against a scratch table, so the counts equal a plain metered run's fuel. The instrument's statics sit above the program's, and the heap moves up by whole pages with the memory, so `memory.grow` runs at the same allocation with and without it.
- `vyrn routes` and `vyrn why` read what generators and the source wrote; they recompute nothing.
- `vyrn doc` writes Markdown only. `docs/api/` is committed and CI checks it with `--verify`.
- `vyrn emit-lowered` is deterministic, promises no format and has no parser.
- The LSP is a synchronous pure adapter over the front end. No generator logic and no input grammar is compiled into it: completion and definition in a foreign grammar are the `vyrnComplete` and `vyrnDefinition` of the claiming generator module's companion, and the rest goes through `//@origin`.
- The editor sends the language server the files the `inputs` globs of `vyrn.json` name, which the server registers with the client per manifest. `.vyx` is a default of the VS Code extension's packaging, not of the server.
- The editor reads an app's CSS only from the files the `stylesheets` globs of `vyrn.json` name; without the key a safelisted class hovers with no rule, because a guess would name one framework's layout.
- The editor never decides which local binding a name names. The check records what each name occurrence in a root body names, by position (`checker::Binders::uses`), and the editor reads it. A token the check did not resolve takes the latest same-named binding at or before its line. A node's `ast::Id` carries the column of the name it spells.
- The LSP gets no incremental parsing, salsa, incremental sync or delta tokens. Lexing and parsing are under 1% of a keystroke; latency came from repeated pure work, fixed by memoizing it.
- A keystroke's load reuses only what one text decides, and links every module again: `link` renames a module's declarations by every module's names, the root's included.
- The LSP trusts its client's file events: under a watched directory it reads a file again only after an event names it. Without the capability it reads the disk on every load, as `vyrn check` does.
- Remote imports are pinned by SHA-256 in `vyrn.lock`, content-addressed in `~/.vyrn/cache`, vendorable and buildable offline. Only `vyrn update` changes a pin. No semver registry.
- A manifest that does not parse is an error, never an empty policy.
- A file another `vyrn` process may read at the same moment (a cache entry, `vyrn.lock`, `vyrn.json`, a vendored blob) is written under a name no other writer uses and renamed into place (`manifest::write_whole`). `vyrn.lock` is saved as this process's changes over the file as it is then, so a pin another build saved survives.
- `vyrn.lock` and `vyrn.json` writes take an OS advisory lock (`File::lock`) on one lock file per project directory, `~/.vyrn/locks/<hash>.files` (`manifest::lock_project_files`), held across reload, merge and rename and never across a build, so the lost update closes.
- A second `vyrn dev` on one project refuses with a sentence naming the first's port. The first holds `~/.vyrn/locks/<hash>.dev` for its life (`manifest::try_lock_dev`), a file of its own beside the save lock, which a server-long hold would block, and records its port in `<hash>.port`.
- `vyrn dev` watches exactly the files its last build read, stamped (modification time and length) before each read, because a build is a function of those files alone; a directory glob would rebuild for files no build reads. It polls the stamps every 50 ms instead of taking a watcher crate: on `examples/shelf` one poll of its 57 files costs 0.6 to 1.5 ms, about 2% of a core, and `notify` 8.2 would bring 7 crates the workspace does not lock, to save at most one 50 ms poll on a build of about 850 ms.
- A `vyrn dev` rebuild restarts the server instance between requests, because data addresses and layouts move between builds; a failed rebuild keeps the last good build serving and reports on stderr and to the page.
- `vyrn serve --workers` refuses a `handle` by the effect judgment's `module-state` verdict (`World::state_path`), which follows a function value as it follows a call. No second walk answers the question.
- The page reloads through server-sent events, injected into dev HTML only. `EventSource` reconnects by itself and needs no client library or framing; a WebSocket needs a handshake and frames for a one-way signal, and long polling needs a request loop of its own.
- A `vyrn` command reads `vyrn.json` and `vyrn.lock` once, into one `Project`. Every load it makes reports through it: the lock is saved, the diagnostics and warnings print one way, and `--offline` and `--deny-warnings` reach every load.
- Tools are pinned per project in the same lock, and bytes are shared per user. A pinned tool that cannot resolve fails; it never falls back to `PATH`.
- clang is discovered and recorded, never pinned, because it links against the host's libc.
- Vyrn does not build tools from source, wrap a package manager, or take a crate for curl, git or tar.
- `vyrn build -o` writes its output through a staged file beside it and a rename (`manifest::stage_beside`), so a reader sees the last build or the new one and a failed build leaves the last one. The native route's intermediates (`<out>.wasm`, `<out>.w2c.c`) stay in place for inspection.
- Native builds choose from a curated set of microarchitectures and always pass `-ffp-contract=off`, because FMA changes float bits.
- The editor grammar colours only words the compiler names, and its keywords equal the lexer's.
- A generator input is analysed through the module that claims it and whose generated code maps to it through `//@origin`. A module claims a file when the first string argument of one of its generator imports resolves to the file or a directory above it; the import graph is the only registry, so there is no extension map.
- One `.vsix` serves every platform; the server ships in each platform's release archive.

## Process

- Each change comes with its numbers: lines before and after, refusals lost and gained, benchmark rows.
- A refusal belongs to the kernel or the checker and is pinned with its sentence. A change reports 0 lost and 0 gained, or says why.
- Output parity cannot see memory. Reclamation is gated by the memory suite and by the exit-residue ratchet, whose leak column may only shrink.
- The free audit is a test instrument built only under `VYRN_LEAK_CHECK`, never shipped in a module.
- A change that moves emitted wasm bytes rewrites the SHA-256 manifest in the same commit and names every moved row.
- Censuses of the type constructors and syntax forms are pinned by tests, so the tables cannot drift.
- Pins are written by gates and merged with the `pin` driver, never by hand.
- A test's scratch directory is its own: `vyrn-cli`'s tests take `common::scratch`, a guard that owns a directory unique to the process and the call and removes it when the test passes, and a helper that would return a path in it returns the guard. A unit test in another crate names its directory with the process id.
- A test sets an environment variable on a child's command, or as the one test of its binary that reads it. `vyrn-lsp` and `vyrn-genwasm` run under `cargo test`, a thread per test, where `set_var` decides by scheduling which test sees it.
- A test of what `vyrn check` says about one program is `tests/check/<name>.vyrn` and its `.stderr`, not a Rust string.
- A prediction is written as a program before the change lands and reported either way. Nothing is deleted until the corpus is green on its replacement.
- A gate that is missed says so; the bar is never moved quietly.
- A red CI run is a diagnosis. For a change to release timing, the Linux job is the gate, because glibc reuses freed memory differently.
- Pre-1.0 changes ship with no deprecation window: the old form is deleted in the same change.
- No builtin has two peer definitions. An oracle checked by a differential test is allowed.
- A benchmark is a claim about a gap: each deviation gets a named defect or missing feature, and the idiomatic program is the one charted.
- Other contestants are held to their own discipline and built with the flags `vyrn build` passes. Published reference numbers are never divided into ours.
- The benchmark harness runs by hand, not in CI; CI checks that each game program still prints its fixture.
- CI times benches only on pushes to `main`, against a baseline taken on CI hardware, with a 2x threshold. `bench --check` is the blocking half.
- No AI attribution in commits, pull requests, code or prose.
- A store evaluates its place, a projection's prologue included, before its value; an element's bounds check runs at the store.
- A store into a binding that outlives a `region` is refused when the stored type holds heap, whatever the depth of the place: `b[0].x = 5` stores an `Int64` and is accepted, `b[0].name = s` is refused.
- A removal (`pop`, `swapRemove`, a map `remove`) through a field or an element is legal in any position, as one through a variable is: `if let Some(v) = r.xs.pop()`, `r.xs.pop() ?? 0`, `f(rs[0].m.remove(k))`. The receiver must be a place.
- A store through a user container expands its `atSet` at the first projected step of the path, at any depth, with the place before the step as the receiver; every index of the receiver that is not a literal or a name runs once, in place order, before the projection reads `self`.
- A removal (`pop`, `swapRemove`, `remove`) through a user container's element shrinks the place that container's `atSet` yields, expanded at the last projected step of the receiver with the steps after it walked from the yielded place; the projection reads its index as often as its body does, as in a read.
- A store reads its leaf index before its value when the value can change it: a `mut` scalar name passed to a call in the value, or module state a call reaches. Other indices are read where they stand. A key that owns heap is moved into the map by the store, so a value that changes it is refused: `m[k.copy()] = f(k)` reads the key first.
- Only a store to a whole name hands the old value back (`xs = xs.push(v)`). A store into a field or an element releases what it overwrites at every depth: a value built from the place's own value was moved out first, and the store fills the hole.
- A store whose value is an alias read through an element or a key (`xs[0] = xs[1]`, `ps[0].name = ps[1].name`, `m["a"] = v` from `m["b"]`) is a take of that alias and is refused with `.copy()`, at every depth and for `i == j` too: the kernel's path erases the index, so it names no one place. Only a path of fields puts an alias back into its own place unchanged (`r.p = r.p`).
- A `let mut` name that owns heap stays an owner for its whole life. A borrow stored into it (`s = xs[1]`, `s = r.a.name`, a map binder) is stored as a copy, by the type's `impl Copy` where it has one, and the store releases the old value. A name that was bound to a borrow and is rebound is a copy from its `let` (#501), so the two rules agree. A store of a borrow does not turn the name into a borrow: that would leave the old value, and every later fresh value, with no owner.
- The `vyrn` binary uses `mimalloc` (2.x, the `v2` feature) as its global allocator, in `vyrn-cli` only. On `site/export.vyrn` it cut `build --target wasm` wall by 37% at 1 and at 12 threads and `test` wall by 25%; peak working set grew 2% to 44%. The v3 default, `snmalloc`, `rpmalloc` and the Windows Segment Heap were measured and lost: v3 and `snmalloc` held 1.6x the system allocator's memory on `test` for no speed gain over v2 (`snmalloc` 5% to 10% faster on the 12-thread build, but it adds a linker warning and needs a C++ toolchain on every platform), `rpmalloc` 2.3x, the Segment Heap gave a quarter of the gain.
- A store into a `modify` parameter name that owns heap releases the value the slot held, as a store into one of its fields does. The caller keeps the slot and owns what it holds after the call, so nothing releases the old value but the store. A `modify` parameter of a type that owns heap is therefore an owner for stores, though not for exits.
- A borrow stored into a `modify` parameter name (`s = ys[0]`, `s = x` over a loop) is stored as a copy, as for a `let mut` name that owns heap. The slot is the caller's, so it must not share a buffer with a place the callee only borrows. The alternative, a refusal with a `.copy()` fix, was weighed and not taken: the store is sound once copied, and the `let mut` form already copies without a refusal.
- `std/sum`'s `sum(xs: Array<Float64>)` is exact: the true sum rounded once to nearest-even, the same bits in any order, IEEE for infinities and NaN, `+0.0` for an exact zero (2026-09-22, built 2026-10-08). A loop with `+` keeps sequential rounding, and the compiler never reorders a float accumulation. The blocked pairwise sum for SIMD speed is a separate named function and is not written: its name, lane count and block size are open.
- The check prover guesses a constant lower bound on a length only from a constant a check needs (one past a literal index, a literal mask or a narrow unsigned index, or a clause's literal) that the producer can make (an array literal it returns, a loop bound by a literal that stores to it); a record field takes the constants a check of that field needs. It guesses a result at least as long as an integer parameter only where a loop bound by that parameter stores to the result or indexes it by its counter. It never guesses from a lattice of constants: each candidate costs a walk.
- `vyrn check` and `vyrn run` read the instantiation limit's refusal off the placer's last lowering (`World::unresolved`) and lower nothing again. A row placed after that lowering dispatches only to an instance it holds (`dispatches_new`), so a lowering of the program as placed stops at the same calls; a change to the placer's fixpoint keeps that true. Of several calls past the limit, the refusal names the first by the callee's line, name and type arguments, not by worklist order.
- A body the emitter lowers never touches the module. Each function index, data address, counted site and stored-closure tag the module decides is a `Log` entry that `merge` fills in source order, so a new kind of module-level request is a new `Log` entry, or the module stops being the same on every thread count.
- The native route caches its fixed objects and its precompiled header under `~/.vyrn/cache/native/<key>/`, keyed by the clang, wasm2c and simde versions, every compile flag and the source hashes; the host object is also keyed by the program's `.w2c.h`, because the host reads `w2c_prog`'s layout from it. A key that differs names a new directory, so a stale entry cannot be found, and a `.sum` file rebuilds a damaged one.
- `tests/fuel.rs` pins the wasmtime fuel of each Benchmarks Game program on its committed input in `tests/pins/fuel.tsv`, and fails when a count grows more than 0.1% over its row (`Fuel-Budget: N%` in a commit body raises the limit, as `Allocs-Budget` does). Fuel counts wasm instructions at wasmtime's prices, exactly and on any machine. It cannot see native code, memory latency, inlining or the length of a `memory.copy`, so a fuel row gates instruction growth and never licenses a speed claim; the timing table does.
- Only the root module's `test` and `bench` blocks are parsed and checked (`parser::parse_imported`). An imported module's blocks are skipped unparsed, whether it is a std module, a project module or a dependency, so an importer pays nothing for them and a broken test fails only its own module. `vyrn test` with no file runs each module of the project that declares a test as its own root. A directory with its own `vyrn.json` or `Cargo.toml` is another project, so the compiler's refused fixtures stay out of the repository's run.
